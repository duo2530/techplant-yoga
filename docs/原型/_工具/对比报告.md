## 方法与口径（重要）

1. **`vision` 工具本次不可用**（HTTP 401，视觉模型 API key 无效），无法按要求对每张对比图调用一次 vision。改为用 `read_image` 把对比图（整图 + 局部放大裁剪）直接读入模型上下文逐张比对，并对关键区块做 2~3 倍放大复核。
2. **对比图在我分析期间被另一进程重写**：`对比\*.png` 的时间戳集中在 15:20:40–15:21:15，`对比\home.png` 于 15:25:05 再次被重写；`_工具\渲染\` 下同时出现 `_vK0/_vK2000/.../_bisect` 等 virtual-time-budget 调试产物 —— 说明有另一个代理正在改动渲染快照。
   为得到一致、可复现的结论，我用独立脚本在 `%TEMP%\dc_cmp\` 重新渲染了一整份快照（Chrome headless，`--virtual-time-budget=12000`，390×844），**本报告的全部结论与数字均基于这份快照**。
   与仓库 `对比\` 目录的当前图相比：messages / my-trials / activities / coaches / terms / privacy / quick-login / phone-auth / forgot-password / native-map / native-location / share-poster 完全一致（MAD=0.00），home(0.30)/booking(0.36)/my-bookings(0.34)/profile(2.42) 有轻微差异。也就是说：**home、booking、my-bookings、profile 四页此前在我第一轮目视中看到的"第 3 张卡片配图空白 + 多出第 4 张卡""门店名折行""多出金牌教练区块"等，在最新渲染中已不复存在，本报告不将其列为问题。**
3. **像素对齐分析**：用 PIL 对左右两栏做逐像素平均绝对差（MAD，0–255）与"差异>40 的像素占比"，并做 ±14px 的平移搜索（用于判断是"整体位移"还是"内容不同"）。数字见文末附录，可用来交叉验证本报告的严重程度排序。
4. **裁剪复核修正**：对比图左右分栏为 `x 0..692` / `x 717..1409`（gap=24）。中途我曾误用 705 作为右栏起点，造成右栏整体右移 12px 的假象（曾据此误判"分享海报文字被放大、末字贴边"）。**分享海报在修正后为像素级一致**，该误判已在报告中剔除。
5. 已知刻意差异不再计为问题：状态栏时间/电量（9:41 vs 11:33 等）、苹方 vs 微软雅黑字形微差、导航栏固定区高约 3–4px。

### 全站共性问题（跨页，优先修）

**A. 底部固定区缺少"底部安全区"，整体贴到屏幕底边**
- 真机 TabBar：栏顶约 CSS y=750，图标中心约 y=777，文字约 y=787，下方留 57px 安全区空白；**总高约 94px**。
- HTML TabBar：栏顶约 CSS y=789，图标 802–822，文字 829，下方仅 15px；**总高约 55px**。
- 结果：四个主页面（home / booking / my-bookings / profile）的 TabBar 图标与文字整体比真机**低 33~42px**，且底部留白严重不足。
- 同一根因在 `trial-apply` 的底部固定操作栏上表现为**整条栏低约 56px**（真机按钮底边距屏底 50px，HTML 只有 4px，视觉上像被裁切）。
- 客观印证：四个带 TabBar 页面的最底部区段（CSS 760–844）MAD 为 7.5–9.0，而**没有** TabBar 的 activities / quick-login 同区段仅 1.4 / 0.9。

**B. TabBar 四个图标字形与真机不同**
真机是"圆角方形徽标"体系：首页=蓝色实心圆角方+白色弧形缺口、约课=圆角方框内一个时钟、已约=圆角方框内一个对勾、我的=实心人形。HTML 用的是 house / calendar-clock / calendar-check / person 线性图标（lucide 风格），且线条更细更浅。文字、颜色、选中逻辑均正确，纯图标造型差异。

**C. 空态插画（SVG 手绘复刻）整体放大约 1.7~2 倍、位置偏移、有裁切、细节丢失**
涉及 home（热门课程）、messages、my-bookings、my-trials。`messages.html` 中插画是内联 SVG（山丘 + 深灰"飞碟" + 3 个纯白椭圆云 + 图片占位框，`#EDEDED/#8E8E8E/#FFFFFF/#E0E0E0`）。问题：① 云朵是纯白，画在同样是白的页面上完全不可见（真机云朵压在灰色山丘上形成明显轮廓）；② 深灰"飞碟"被山丘路径压住、只露出一小条；③ 外层尺寸设为 166×80，比真机（约 88 CSS px 宽）大一倍左右；④ 容器高度不足时底部被硬边裁切。

# 用例：维护排课

## 概览

**用例编号：** UC-009
**用例名称：** 维护排课
**主要参与者：** 平台管理员
**参与方：** 排课、门店、课程、教练、教室（业务模块）
**业务目标：** 为某门店排出可对用户端展示的**排课**（门店 ＋ 课程 ＋ 教练 ＋ 教室 ＋ 日期与起止时间 ＋ 最大人数 ＋ 最低开课人数），并维护其状态（上架／下架／取消）与删除。
**涉及模块：** 排课、门店、课程、教练、教室
**状态：** 已确认

> 依据：[`业务规则.md`](../../需求文档/业务规则.md) v2.1。

## 前置条件

- 管理员已登录管理端（[UC-004](UC-004-管理端登录.md)）。
- 门店、课程、教练、教室均已存在且未删除；教室的归属门店与排课门店一致。
- 开始时间早于结束时间、不跨自然日；最大人数大于 0；最低开课人数不小于 1 且不大于最大人数。
- 排课日期在今天起 14 天范围内。

## 主成功场景

1. 管理员查询**排课列表**（可按门店、课程、教练、日期、**状态**筛选）与排课详情；列表展示状态，「已预约人数」**只读**；
2. **新增排课**：选择门店、课程、教练、教室，设置日期、开始时间、结束时间、最大人数与最低开课人数（默认 2 人）；**课种由系统从所选课程写入快照**，**上课日期由系统从开始时间推导**，两者都不接受手工提交；
3. 应用校验：门店／课程／教练存在且未删除；教室存在且归属门店与排课门店一致；开始早于结束且不跨自然日；最大人数大于 0；1 ≤ 最低开课人数 ≤ 最大人数；日期在今天起 14 天内；
4. 应用校验**唯一性与冲突**：同一门店 ＋ 同一课程 ＋ 完全相同的日期与起止时间不得重复；**同一教练任意两节排课的时间不得重叠**；
5. 应用保存排课：状态为**待上架**，「已预约人数」初始化为 0；
6. **状态流转**：上架（待上架 → 已上架）、下架（已上架 → 待上架）、取消（已上架 → 已取消）；
7. **修改排课**：**只有「待上架」的排课可修改**（已上架须先下架再改）；已取消与已结束不可修改；**更换课程时刷新课种快照**；
8. **删除排课**：只允许删除**待上架**的排课；已上架须先下架后才能删除；
9. 排课**上架后**进入用户端可查范围；**取消后仍在用户端可见（标注为已取消）**；**下架（回到待上架）后不再可见**（[UC-002](UC-002-浏览约课页.md)）；管理员在列表中核对结果。

## 替代流程

- **A1 门店、课程、教练或教室不存在／已删除**：拒绝保存。
- **A2 教室归属门店与排课门店不一致**：拒绝保存。
- **A3 时间非法**（开始不早于结束、或跨自然日）：拒绝保存。
- **A4 最大人数不大于 0，或最低开课人数小于 1／大于最大人数**：拒绝保存。
- **A5 日期超出今天起 14 天**：拒绝保存。
- **A6 同一门店＋同一课程＋完全相同的日期与起止时间已存在**：拒绝；时间重叠但起止时刻不同的本版放行。
- **A7 同一教练的时间与其它排课重叠**：**拒绝保存**，不做"提示后放行"。
- **A8 对非「待上架」的排课发起修改**（已上架／已取消／已结束）：拒绝并提示**先下架**；已取消与已结束是终态，也不允许"恢复为可编辑"。
- **A9 对已上架的排课发起删除**：拒绝，须先下架；对已取消或已结束的排课发起删除同样拒绝。
- **A10 重复设置当前已生效的同一状态**（如连续两次上架）：按**成功**处理（幂等）。
- **A11 目标状态只能是待上架、已上架或已取消**：不接受把排课直接置为"已结束"。
- **A12 「已结束」不落库**：由「结束时间不晚于当前时间」推导，管理端展示为已结束；不提供"已结束"的状态维护入口。
- **A13 一期不做「不足最低开课人数自动取消」**：最低开课人数只做录入、范围校验与用户端展示，**不设定时任务、不触发任何自动行为**。
- **A14 一期不做热门标记**：排课不设热门标识与热门排序值。
- **A15 私教排课不由管理员维护**：一期没有私教排课与私教预约，管理端排课里不出现私教。
- **A16 排课不存在或已删除**：拒绝查询详情、修改、状态变更与删除。
- **A17 保存失败**：不生成或改动任何排课数据。

## 后置条件

### 成功后的状态

- 生成或更新一条排课，含门店、课程、教练、教室、日期与起止时间、最大人数、最低开课人数与状态；
- 新增排课的「已预约人数」为 0，剩余名额等于最大人数；
- 排课处于**非「待上架」**时，用户端可按「门店 ＋ 日期」查到（已上架、**已结束**、**已取消**都可见）；
- 该教练此时段被视为已占用，不能被其它排课重复排入。

### 失败后的状态

- 不生成也不改动排课数据；
- 既有的排课、门店、课程、教练、教室不受影响。

| BR-排课-002 | 开始早于结束；不跨自然日 |
| BR-排课-003 | 最大人数大于 0 |
| BR-排课-004 | 最低开课人数不小于 1 且不大于最大人数，默认 2 |
| BR-排课-005 | 不做不足最低开课人数的自动取消 |
| BR-排课-006 | 门店／课程／教练／教室的存在性与归属校验 |
| BR-排课-007 | 同门店＋课程＋完全相同起止时间不重复 |
| BR-排课-008 | 同一教练的时间不得重叠，重叠即拒绝 |
| BR-排课-009 | 只能排今天起 14 天内 |
| BR-排课-010 | 落库状态只有待上架／已上架／已取消；「已结束」不落库 |
| BR-排课-011 | 新增排课默认待上架 |
| BR-排课-012 | 状态流转三条；没有"已下架"；已取消与已结束是终态 |
| BR-排课-013 | **只有「待上架」可编辑**；已上架须先下架；已取消与已结束不可编辑 |
| BR-排课-021 | 排课保存**课种快照**（新增与更换课程时写入，客户端不可提交） |
| BR-排课-022 | 排课保存**独立日期列**（由开始时间推导，客户端不可提交）；日期筛选一律按它 |
| BR-排课-014 | 只允许删除待上架的排课；已上架须先下架；已取消与已结束不得删除 |
| BR-排课-015 | 用户端展示除「待上架」以外的排课；下架（回到待上架）后不可见，取消后仍可见 |
| BR-排课-017 | 用户端日期范围为今天起 14 天，与本用例的排课窗口一致 |
| BR-排课-019 | 已预约人数只允许预约模块维护，管理端表单只读 |
| BR-排课-020 | 管理端排课列表展示状态并支持按状态筛选 |
| BR-课程-009 | **课种在排课时做快照**；难度／封面／介绍仍实时取课程 |
| BR-门店-009、BR-教室-006、BR-教练-006、BR-课程-008 | 本用例创建的排课会构成这些主数据的删除门禁 |
| BR-全局-009 | 删除门禁统一口径 |
| BR-全局-006、BR-全局-007、BR-全局-008 | 主体不存在即拒绝；引用检查失败不降级放行；状态重复设置幂等 |
| BR-全局-005 | 一期不纳入私教排课、自动取消与热门标记 |

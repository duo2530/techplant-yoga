# 用例：维护教室资料

## 概览

**用例编号：** UC-006
**用例名称：** 维护教室资料
**主要参与者：** 平台管理员
**参与方：** 教室、门店、排课（业务模块）
**业务目标：** 维护门店下的**教室**（查询、新增、改名、删除），为排课表单提供教室来源，并保证教室归属与排课门店一致。
**涉及模块：** 教室、门店、排课
**状态：** 已确认

> 依据：[`业务规则.md`](../../需求文档/业务规则.md) v2.1。

## 前置条件

- 管理员已登录管理端（[UC-004](UC-004-管理端登录.md)）。

## 主成功场景

1. 管理员查询**教室列表**（可按所属门店筛选）与教室详情；
2. **新增教室**：选择所属门店并填写教室名称；应用校验所属门店存在且未删除，并校验**同一门店内教室名称不重复**；
3. **修改教室**：**只允许修改名称**，不允许修改所属门店；改名不加排课门禁；
4. **删除教室**：**物理删除**；删除前校验该教室名下**没有未结束、且状态为待上架或已上架的排课**；
5. 应用返回维护结果，管理员在列表中核对。

## 替代流程

- **A1 同一门店内教室重名**：拒绝新增或修改。
- **A2 所属门店不存在或已删除**：拒绝新增。
- **A3 教室名下仍有未结束且待上架／已上架的排课**：拒绝删除，并给出数量。
- **A4 只有已取消或已结束的历史排课引用该教室**：**不阻塞删除**。
- **A5 统计无法完成**（统计异常）：拒绝删除，**不降级放行**。
- **A6 修改请求携带门店字段**：忽略——教室只允许改名称；换门店等价于删除后在新门店下重建。
- **A7 教室没有状态**：不做启用／停用，也不存在「维修中」「占用中」，不提供状态维护入口。
- **A8 教室不承载容量、设备、图片、楼层、坐标等扩展信息**：不建字段、不提供入口。
- **A9 改名与删除都不追溯**：教室被删除后，引用它的历史排课**不失效**，仅该排课的教室显示为空，管理端做空值兜底。
- **A10 教室不存在或已删除**：拒绝查询详情、修改与删除。
- **A11 排课所选教室必须归属排课门店**：由排课用例（[UC-009](UC-009-维护排课.md)）校验，本用例不校验教室的时间冲突。

## 后置条件

### 成功后的状态

- 新增与改名结果落库，并可按门店查询到；
- 删除为物理删除，删除后该名称随即释放、可再次使用；
- 教室可作为排课表单的教室来源，并受「归属门店与排课门店一致」的约束。

### 失败后的状态

- 教室数据保持原值；
- 删除被拒绝时，教室及其关联排课数据均不受影响。

## 业务规则

| 规则编号 | 在本用例中的作用 |
|---|---|
| BR-教室-001 | 教室归属门店；同一门店内名称不得重复 |
| BR-教室-002 | 教室字段只有所属门店与名称，不承载扩展信息 |
| BR-教室-003 | 教室没有状态 |
| BR-教室-004 | 只允许改名称，不允许改所属门店 |
| BR-教室-005 | 排课所选教室必须存在，且归属门店与排课门店一致 |
| BR-教室-006 | 教室可删除且为物理删除，名称随即释放 |
| BR-教室-007 | 删除后历史排课不失效，仅教室显示为空 |
| BR-全局-009 | 删除门禁统一口径：只统计未结束且待上架／已上架的排课 |
| BR-全局-006 | 主体不存在或已删除时一律拒绝 |
| BR-全局-007 | 引用检查失败即拒绝，不降级放行 |
| BR-门店-001 | 教室是门店下设的场地 |
| BR-门店-009 | 门店删除时，名下有教室即拒绝 |

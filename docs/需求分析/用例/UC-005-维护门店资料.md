# 用例：维护门店资料

## 概览

**用例编号：** UC-005
**用例名称：** 维护门店资料
**主要参与者：** 平台管理员
**参与方：** 门店、教室、排课（业务模块）
**业务目标：** 维护平台的**门店**主数据（查询、新增、修改、删除），为用户端门店切换与排课提供门店来源。
**涉及模块：** 门店、教室、排课
**状态：** 已确认

> 依据：[`业务规则.md`](../../需求文档/业务规则.md) v2.1。

## 前置条件

- 管理员已登录管理端（[UC-004](UC-004-管理端登录.md)）。

## 主成功场景

1. 管理员查询**门店列表**（可按门店名称、所在区域、门店类型筛选）与门店详情；
2. **新增门店**：填写门店名称、门店类型、所在区域 code、联系电话、营业时间、地址、门店图片（**单图**）；应用校验门店名称唯一，并校验区域 code 在字典内；
3. **修改门店**：修改上述资料；名称同样校验唯一（排除自身）；已被排课引用时仍允许修改；
4. **删除门店**：**物理删除**；删除前校验①名下**没有教室**，②没有**未结束、且状态为待上架或已上架**的排课引用；
5. 应用返回维护结果，管理员在列表中核对。

## 替代流程

- **A1 门店重名**：拒绝新增或修改。
- **A2 门店类型不在枚举内**：拒绝（枚举只有**主力店、精品店**）。
- **A3 所在区域 code 不在字典内**：拒绝（字典 `store_region`，上海市 16 个市辖区）。
- **A4 名下仍有教室**：拒绝删除，并给出教室数量。
- **A5 仍被未结束、且待上架或已上架的排课引用**：拒绝删除，并给出排课数量。
- **A6 只有已取消或已结束的排课引用该门店**：**不阻塞删除**；删除后这些历史排课上的门店显示为空，管理端做空值兜底。
- **A7 统计无法完成**（统计异常）：拒绝删除，**不降级放行**。
- **A8 门店没有启用／停用状态**：不提供状态维护入口。
- **A9 请求携带状态字段**：忽略——状态字段不随新增或修改请求提交；重复设置同一状态按成功处理。
- **A10 门店不存在或已删除**：拒绝查询详情、修改与删除。
- **A11 门店只留联系电话**：一期**不建**「经营类型」字段（只做直营连锁），也**不设「联系人」**。

## 后置条件

### 成功后的状态

- 新增与修改结果落库，门店可被用户端门店列表与排课表单查询到；
- 删除为物理删除，删除后该门店不再出现；其历史排课上的门店显示为空。

### 失败后的状态

- 门店数据保持原值；
- 既有教室、排课不受影响。

## 业务规则

| 规则编号 | 在本用例中的作用 |
|---|---|
| BR-门店-001 | 门店是浏览与排课的服务地点；下设教室、承载排课 |
| BR-门店-002 | 用户端门店列表只返回未删除的门店 |
| BR-门店-003 | 门店名称唯一，不允许重名 |
| BR-门店-004 | 门店类型固定枚举：主力店、精品店 |
| BR-门店-005 | 所在区域存上海市市辖区**行政区划 code**，取值与区名翻译都走字典 `store_region` |
| BR-门店-006 | 营业时间只保存一段固定展示文本 |
| BR-门店-007 | 门店字段范围（名称／类型／区域 code／电话／营业时间／地址／单图；**不含联系人**） |
| BR-门店-008 | 门店没有启用／停用状态 |
| BR-门店-009 | 门店删除为物理删除，须过删除门禁且名下无教室 |
| BR-门店-010 | 已被排课引用时仍允许编辑门店资料 |
| BR-全局-009 | 删除门禁统一口径：只统计未结束且待上架／已上架的排课 |
| BR-全局-006 | 主体不存在或已删除时一律拒绝 |
| BR-全局-007 | 引用检查失败即拒绝，不降级放行 |
| BR-全局-008 | 重复设置已生效的同一状态按成功处理 |
| BR-全局-005 | 门店经营类型不纳入一期 |

# 用例：维护教练资料

## 概览

**用例编号：** UC-007
**用例名称：** 维护教练资料
**主要参与者：** 平台管理员
**参与方：** 教练、排课（业务模块）
**业务目标：** 维护**平台级**的教练主数据（查询、新增、修改、删除），并通过独立操作维护**金牌教练等级**，为排课提供可选教练，为用户端首页金牌教练栏目、排课卡片与课程详情页提供教练信息。
**涉及模块：** 教练、排课
**状态：** 已确认

> 数据与接口契约见[教练管理详细设计](../../详细设计/教练管理详细设计.md)和[用户端接口详细设计](../../详细设计/用户端接口详细设计.md)。

## 前置条件

- 管理员已登录管理端（[UC-004](UC-004-管理端登录.md)）。

## 主成功场景

1. 管理员查询**教练列表**与教练详情，列表与详情显示教练**等级**（普通教练／金牌教练）；
2. **新增教练**：填写姓名、头像、简介、联系电话、相册（**最多 5 张**）；新增教练固定为**普通教练**；
3. **修改教练**：修改上述资料；资料编辑**不改变等级**；
4. **设置／取消金牌**：已登录管理员在列表操作列选择「设为金牌」或「取消金牌」，二次确认后生效；重复设置同一等级按成功处理；
5. **删除教练**：**物理删除**；删除前校验该教练名下**没有未结束、且状态为待上架或已上架的排课**；
6. 应用返回维护结果，管理员在列表中核对；金牌等级变化影响用户端首页「金牌教练」栏目。

## 替代流程

- **A1 教练名称重复**：**放行**——教练名是人名，同名不同人客观存在，不构成唯一性约束。
- **A2 相册超过 5 张**：拒绝。
- **A3 教练名下仍有未结束且待上架／已上架的排课**：拒绝删除，并给出数量。
- **A4 只有已取消或已结束的历史排课引用该教练**：**不阻塞删除**；删除后这些历史排课上的教练显示为空，管理端做空值兜底。
- **A5 统计无法完成**（统计异常）：拒绝删除，**不降级放行**。
- **A6 一期不设教练技能（可授课程）**：不建该字段，排课时不按技能过滤。
- **A7 等级由独立接口维护**：新增与资料编辑请求不接收也不修改等级；管理员通过「设为金牌／取消金牌」单独维护。
- **A8 一期不设手动排序值**：不建该字段。
- **A9 教练不归属门店、不与门店建立关联**：排课时直接从教练列表中选择，不做「按门店取教练」；金牌教练列表同样是平台级，不按门店过滤。
- **A10 教练不存在或已删除**：拒绝查询详情、修改、删除与等级设置，提示教练不存在。
- **A11 用户端不提供「全部教练列表」**：用户端页面为首页金牌教练栏目与单教练「约教练」页；教练信息仍出现在排课卡片与课程详情页上。
- **A12 管理端身份校验**：游客和只有会员身份的调用者不能维护等级；已登录管理员无需独立等级按钮权限即可设置或取消金牌。
- **A13 重复设置同一等级**：按成功处理，等级保持目标值，不产生重复数据。
- **A14 设置等级目标值非法**：拒绝并返回参数错误，等级不变。

## 后置条件

### 成功后的状态

- 新增与修改结果落库，教练可被排课表单查询到；
- 等级变更落库：金牌教练出现在用户端首页「金牌教练」栏目，取消金牌后不再出现（已打开的教练资料页仍可访问）；
- 删除为物理删除，删除后该教练不再出现在排课表单的可选项中；其历史排课上的教练显示为空。

### 失败后的状态

- 教练数据保持原值，等级保持原值；
- 既有排课不受影响。

## 业务规则

| 规则编号 | 在本用例中的作用 |
|---|---|
| BR-教练-001 | 教练为平台级主数据，不归属门店、不与门店关联 |
| BR-教练-002 | 教练名称允许重名 |
| BR-教练-003 | 教练字段范围（本版新增等级字段：1 普通教练／2 金牌教练） |
| BR-教练-004 | 相册上限 5 张 |
| BR-教练-006 | 教练可删除且为物理删除，须过删除门禁 |
| BR-全局-009 | 删除门禁统一口径：只统计未结束且待上架／已上架的排课 |
| BR-全局-006 | 主体不存在或已删除时一律拒绝 |
| BR-全局-007 | 引用检查失败即拒绝，不降级放行 |

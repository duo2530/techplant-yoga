## 4. 关键口径速查（★ = 最容易搞错）

### 4.1 用户端

| 项 | 口径 |
|---|---|
| ★ **导航形态** | 底部 **4 个 tab**：首页 / 约课 / 在约 / 我的；**「在约」与「我的」是一期空页**，不接任何接口；约课页是**一级 tab 页**，不做二级页、不需要返回箭头 |
| ★ **可见口径** | **`status <> 1`（非「待上架」）**：已上架、**已结束**、**已取消**都可见，**只有待上架不可见**。❌ 不是"已上架且未结束" |
| ★ **用户端状态文案** | **可约 / 已结束 / 已取消**（管理端才是 待上架／已上架／已取消／已结束） |
| ★ **已取消/已结束的卡片** | **可以点进课程详情页**，只是「立即预约」不可点（`bookable = false`） |
| 功能页面 | 只有 **3 个**：首页（**只做门店切换**）、约课页、课程详情页 |
| 首页门店列表 | **分页** ＋ 按 `regionCode` 筛选 ＋ `keyword`（**同时匹配门店名称与地址**） |
| 约课页 | 课种 Tab **四类** ＋ 日期条**今天起 14 天**（默认今天）＋ **分页** |
| 卡片要素 | **课程封面**、课程名称、课种、难度、时间、教练、门店、教室、剩余名额、**状态** |
| 详情页要素 | 上列 ＋ 课程介绍、教练**姓名/头像/简介**、最大人数、最低开课人数、预约人员（空）、剩余名额 |
| 接口 | **3 个免登录只读**：`GET /api/stores`、`GET /api/schedules`、`GET /api/schedules/{id}`；**都分页**（`TableDataInfo`） |
| 当前门店 | 存小程序**本地存储**，不落服务端、不登录 |
| 一期不做 | 地址跳地图、收藏、分享、打卡、公告、今日可约、热门课程、金牌教练、门店实景图 |

### 4.2 排课（本期核心）

| 项 | 口径 |
|---|---|
| ★ **状态** | 落库只有 **`1` 待上架 / `2` 已上架 / `3` 已取消**；**「已结束」不落库**，由 `end_time <= 现在` 推导 |
| ★ **判定落点** | **在 service 层判定**（返回 controller 之前一次判定），产出 `finished` / `statusText` / `bookable`；controller 不判断、前端不算。**唯一例外**：删除门禁的 **count 查询**把 `end_time > 现在` 写在 **SQL 条件**里 |
| ★ **编辑门禁** | **只有「待上架」可编辑**；已上架要先**下架**（回到待上架）再改；已取消与已结束是**终态** |
| ★ **删除门禁** | **只有「待上架」可物理删除**；已上架须先下架 |
| ★ **课种快照** | `t_schedule.course_type` 由服务端从课程复制、**不接受客户端提交**；**只有「新增排课」与「更换课程」两处写入**；课程事后改课种**不追溯**；但**难度/封面/介绍仍实时取课程**（改难度会影响既有排课展示） |
| ★ **日期列** | `schedule_date` 由 `start_time` 推导、改时间同步刷新；**日期筛选一律按它**，不用 start/end 拼 |
| **状态流转** | 只有 `1→2`（上架）、`2→1`（下架＝回到待上架）、`2→3`（取消）；**没有「已下架」这个状态**；重复设同一状态**幂等成功** |
| **两条冲突校验** | ① **同一教练任意两节排课的时间区间不得相交**（硬拒绝，不做"提示后放行"）② 同门店＋课程＋**完全相同的日期与起止时间**不得重复；两条都在**同一事务**内校验 |
| **不建唯一索引** | 因为"教练时间不重叠"是区间相交无法索引；而"完全相同起止时间"若建唯一索引，**取消后就再也排不回同一时段**（MySQL 无部分唯一索引） |
| 排课窗口 | 只能排**今天起 14 天内** |
| 人数 | `max_persons > 0`；`1 <= min_persons <= max_persons`（默认 2）；`booked_persons` 一期固定 0、表单只读 |
| 一期不做 | 「不足最低开课人数自动取消」、定时任务、热门标记、已有预约时的变更限制（没有预约可影响） |
| 取消的级联 | 一期**无级联**（没预约可取消、没次数可返还、没通知要发） |

### 4.3 主数据与横切

| 项 | 口径 |
|---|---|
| ★ **删除方式** | **5 张业务表一律物理删除**：不建 `deleted`、**不用 `@TableLogic`**（与 `backend/AGENTS.md` §6 旧约定**有意不同**） |
| ★ **删除门禁** | 门店/教室/教练/课程被**「未结束且状态为待上架或已上架」**的排课引用 → 拒绝并给出数量；**已取消与已结束不阻塞**；**统计失败也拒绝**（fail-closed）；删除后历史排课上的对象显示为空；**门店另加一条：名下有教室也拒绝** |
| ★ **枚举返回** | **码与名称成对返回**：`courseType`＋`courseTypeName`、`regionCode`＋`regionName`、`status`＋`statusText`；**前端不维护"码 → 名"映射** |
| ★ **跨模块** | **不跨模块读表、不另立 QueryService**；一律直接依赖对方模块的 **Service**；调用失败 **fail-closed** |
| **无状态的对象** | **门店、教室、课程都没有状态字段**（只有排课有状态） |
| 门店区域 | 存**行政区划 code（6 位）**；区名由**字典 `store_region`**（16 条）翻译；**代码里不另维护 Java 枚举** |
| 门店其他 | 名称**唯一**；门店类型枚举（主力店/精品店）；图片**单图**；**不设「联系人」**、**不设「经营类型」** |
| 教室 | 归属门店、**同门店内名称唯一**；只允许**改名称**（不允许换门店）；**没有详情接口**；无状态、无容量/设备 |
| 教练 | **平台级、不关联门店**；**不设**技能/头衔/金牌/手动排序；名称**允许重名**；相册用 **`gallery json`**（≤5 张，**不建子表**） |
| 课程 | **平台级、不归属门店**；名称**全平台唯一**；课种四类（**私教课枚举保留但一期不使用**）；难度 1~5 星；封面单图；**无状态、无展示排序** |
| 鉴权 | 用户端 3 个接口 `@Anonymous` 只读；管理端**只要求已登录**；**不做 RBAC、不发明权限串**；**若依自带的「系统管理」菜单完全不动** |
| 菜单 | 一级目录 `2000`「经营基础」：`2001` 门店 / `2002` 教室 / `2003` 教练 / `2004` 课程 / `2005` 排课 |
| 图片上传 | 用若依自带的 **`POST /common/upload`**，**存本地文件**，**数据库只存 URL**；门店图片/教练头像/教练相册/课程封面**四处复用**。⚠️ `ruoyi.profile` 现为 `D:/ruoyi/uploadPath`（Windows 硬编码），**部署前要改** |
| 响应 / 异常 | HTTP 固定 200，看 `code`；业务码 `200/401/404/409/500`；**`@Valid` 失败是 500**（框架既有行为，一期不改）；业务失败抛 `ServiceException` |
| 分页 | `Query` → MyBatis-Plus `IPage` → `PageResult` → `TableDataInfo`；**必须有稳定排序**；上限 100；**不要用 `startPage()` + PageHelper** |
| 时间格式 | `yyyy-MM-dd HH:mm:ss`；日期 `yyyy-MM-dd` |
| 主键 | `bigint unsigned` 雪花 ID，应用侧生成；返回前端时序列化为**字符串** |

## 1. 一期范围与验收

| 项 | 内容 |
|---|---|
| **一句话目标** | **能看**：管理端把门店、教室、教练、课程、排课维护起来，用户端**免登录**能按门店看到排课并进入课程详情 |
| **两个端** | **用户端**（微信小程序，**免登录**）、**管理端**（**平台管理员**，用户名 ＋ 密码登录） |
| **五个对象** | 门店、教室、教练（平台级）、课程（平台级）、排课 |
| **一期验收口径** | 管理端能建好门店与教室、平台级教练与课程，并排出一节**已上架**的排课；用户**不登录**即可在首页切换门店、在约课页看到这节排课、点进去看到课程资料与本次上课信息；点「立即预约」提示**敬请期待** |
| **一期不产生** | 任何**预约数据**（没有预约、会员、会员卡、签到、通知） |

**一期项数基线：** 功能 **51 项**（用户端 12 ＋ 管理端 39）；活动 **9 个**；施工波次 **6 个**；接口 **28 个**（管理端 26 ＋ 用户端 2 个新增，另有 1 个用户端接口在 W1 交付）；业务表 **5 张**。

## 2. 视图一 · 用户旅程地图（心智模型）

> 不是流程图，是"**谁在什么场景下用哪几页**"。它决定波次里哪些页面必须同时可用。

### 2.1 用户旅程（小程序 · **全程免登录**）

```text
① 进入小程序
   └─ 首页：看到「当前门店」的门店卡（门店名称 / 所在区域 / 地址）
       └─ 点「换店」
           └─ 门店列表（分页；可按区域筛选、按名称或地址搜索）
               └─ 选中 → 当前门店更新（只存在手机本地）

② 从首页进约课页
   ├─ 课种 Tab：团课 / 精品课 / 私教课 / 特色课   ← 按排课的「课种快照」筛
   ├─ 日期条：今天起 14 天，默认选中今天        ← 按排课的「上课日期」列筛
   └─ 排课卡片列表（分页加载）
        卡片：课程名称 · 课种 · 难度 · 时间 · 教练 · 门店 · 教室 · 剩余名额 · 状态
        状态只有三种：可约 / 已结束 / 已取消     ← 待上架不出现

③ 点某张卡片
   └─ 课程详情页
        课程资料：封面 · 课种 · 难度 · 介绍
        本次上课：时间 · 教练（姓名/头像/简介）· 门店 · 教室
        人数信息：最大人数 · 最低开课人数 · 预约人员（一期为空）· 剩余名额
        「立即预约」→ 点击提示「敬请期待」（不发起任何请求）
```

**这条旅程对开发的含义：**

- 全程**没有登录页、没有"我的"、没有会员卡**——一期用户端只有 **3 个页面**。
- 「已取消」和「已结束」的场次**照常展示**（置灰、不可预约），**不是过滤掉**——这一条已按真实 App 的场次状态（立即预约／排队／已取消／已结束）纠正过。
- 课种与日期**都由排课的派生列承担**（`course_type` 快照、`schedule_date`），所以**排课不落地就看不到任何东西**。

### 2.2 运营旅程（管理端 · 平台管理员）

```text
① 登录（用户名 ＋ 密码，沿用若依脚手架）

② 建门店
   └─ 门店管理：名称（唯一）· 类型（主力店/精品店）· 所在区域（字典选）· 电话 · 营业时间 · 地址 · 图片（单图）
       ※ 没有"门店状态"、没有"经营类型"、没有"联系人"

③ 在门店下建教室
   └─ 教室管理：所属门店 ＋ 名称（同门店内不重名）     ※ 没有状态，没有容量/设备，没有详情页

④ 建平台级课程与教练（与门店无关）
   ├─ 课程管理：名称（全平台唯一）· 课种（四类）· 封面（单图）· 介绍 · 难度（1~5 星）
   └─ 教练管理：姓名（可重名）· 头像 · 简介 · 联系电话 · 相册（≤5 张）

⑤ 排课
   └─ 排课管理：选门店 → 选课程 → 选教练 → 选教室 → 日期与起止时间 → 最大人数 + 最低开课人数
       · 保存后状态 = 待上架（用户端看不到）
       · 点「上架」→ 用户端才看得到
       · 要改已上架的课：先「下架」→ 改 → 再「上架」
       · 点「取消」→ 已取消（用户端仍可见，标注为已取消）
```

**这条旅程对开发的含义：**

- **顺序不能乱**：门店 → 教室 → 课程/教练 → 排课。排课同时引用四个对象，缺一录不进去。
- **只有排课有状态**，门店／教室／课程都没有状态字段。
- **四个主数据都有删除门禁**：被「未结束、且状态为待上架或已上架」的排课引用时**拒绝删除**；门店另加一条"名下有教室也拒绝"。

### 2.3 两条旅程与波次的关系

```text
用户旅程的关键节点            它依赖的波次
─────────────────────────────────────────────
首页门店卡 / 换店        ←──  W1 门店（含 GET /api/stores）
约课页看到排课           ←──  W4 排课（课种快照 + 上课日期列）
课程详情页               ←──  W4 排课
（管理端一切）           ←──  W1~W3 基础数据，W4 排课
```

> **注意 C1 可以提前**：用户端首页只依赖 W1（门店），**不必等到 W4**。若想早点看到"能切门店"，W1 完成后即可做 C1 的联调。

## 3. 视图二 · 施工波次（依赖顺序）

```text
W1 · 门店（6 接口：管理端 5 + 用户端 1）        ← 地基：教室归属它、排课引用它
        │
W2 · 教室（4 接口）+ 课程（5 接口）              ← 教室依赖 W1；课程完全独立
        │
W3 · 教练（5 接口）                              ← 独立
        │
W4 · 排课（6 接口）                              ← 依赖 W1~W3 全部就绪
        │
W5 · 用户端首页（C1）                            ← 只依赖 W1，可提前到 W1 之后
        │
W6 · 用户端约课页 + 课程详情页（C2/C3）          ← 依赖 W4
```

> **W1~W3 对应《活动清单》的「阶段一 · 基础数据」**（那里是"四项并行"），这里按依赖关系再排了先后。W2 与 W3 可以互换或并行。

| 风险 | 这是唯一同时依赖四个模块的地方，**联调量最大**；建议单独跑一轮"四对象不存在／已删除"的异常路径 |

## 5. 一期接口总清单（按波次）

> **路径前缀**：管理端 `/admin/**`（要求登录）；用户端 `/api/**`（**免登录只读**，标 `@Anonymous`）。
> **返回体**：单条 `AjaxResult{code,msg,data}`；列表 `TableDataInfo{total,rows,code,msg}`。

### 5.1 W1 · 门店（6）

| # | 方法 | 路径 | 功能 | 端 |
|---:|---|---|---|---|
| 1 | GET | `/admin/stores` | 查询门店列表（名称／区域／类型） | 管理端 |
| 2 | GET | `/admin/stores/{storeId}` | 查询门店详情 | 管理端 |
| 3 | POST | `/admin/stores` | 新增门店 | 管理端 |
| 4 | PUT | `/admin/stores/{storeId}` | 修改门店 | 管理端 |
| 5 | DELETE | `/admin/stores/{storeId}` | 删除门店（物理，带门禁） | 管理端 |
| 6 | GET | `/api/stores` | 门店列表（**分页 ＋ 区域筛选 ＋ 名称/地址关键字**） | **用户端** |

### 5.2 W2 · 教室（4）＋ 课程（5）

| # | 方法 | 路径 | 功能 | 端 |
|---:|---|---|---|---|
| 1 | GET | `/admin/classrooms` | 查询教室列表（按门店筛选） | 管理端 |
| 2 | POST | `/admin/classrooms` | 新增教室 | 管理端 |
| 3 | PUT | `/admin/classrooms/{classroomId}` | 修改教室（**只改名称**） | 管理端 |
| 4 | DELETE | `/admin/classrooms/{classroomId}` | 删除教室（物理，带门禁） | 管理端 |
| 5 | GET | `/admin/courses` | 查询课程列表（名称／课种） | 管理端 |

## 8. 已拍板的口径（**全部已定**）

| # | 事项 | **结论** |
|---:|---|---|
| 1 | 既有旧代码怎么处理 | **就地改造**。按新详细设计**逐字段核对**，删掉多余列与逻辑删除；`classroom` 现有三个半成品包（dao/domain/mapper）可直接覆盖重写 |
| 2 | 旧页面怎么处理 | **保留、不删除**。小程序里 10 个旧页面与旧的范围（活动／体验课／我的预约／我的／登录／分享／协议／消息）＋管理端 `views/booking`，一期**不接入口、不做联调**，也不动它们；结项时再统一清理 |
| 3 | 「已结束」的判定落在哪一层 | **落在 service 层**：**返回 controller 之前**由 service 统一判定一次——`end_time <= 当前时间` 即**已结束**，并据此产出 `finished`、`statusText`、`bookable`。**controller 不做判断、前端不算、也不用为派生状态再查一次库。**<br>⚠️ **唯一例外**：删除门禁的**计数**（"有没有未结束的排课引用我"）是 count 查询，`end_time > 当前时间` 必须写在 **SQL 条件**里——不能把行拉回内存再筛。**这一处是刻意保留的第二个表达式，改口径时两处一起改。** |
| 4 | 图片上传怎么存 | **用若依自带的上传能力**：`POST /common/upload`（单文件）／`POST /common/uploads`（多文件），**存本地文件**，上传后**返回图片地址**，**数据库只存这个 URL**。<br>门店图片、教练头像、教练相册、课程封面**四处复用同一套**。<br>⚠️ 上传根目录现在是 `application.yml` 里的 `ruoyi.profile: D:/ruoyi/uploadPath`（Windows 硬编码），**部署到服务器前必须改成实际路径**。 |
| 5 | 门店区域字典的 16 个 code | **按 [门店管理详细设计 §1.2.2](../详细设计/门店管理详细设计.md) 的表执行**——上海市 16 个市辖区的**行政区划代码**（`310101` 黄浦区 … `310151` 崇明区）。灌 `sys_dict_data` 种子时**逐条核对一遍**即可，不需要额外决策。 |
| 6 | 管理端默认账号改密 | **本期先不做**，不纳入一期验收；上线前再统一处理（连同 `/druid/*` 监控台的默认口令与白名单）。 |
| 7 | 删除门禁的占位实现怎么收口 | W1~W3 时**排课模块还不存在**，而门店／教室／教练／课程的删除都要先问"有没有被排课引用"。做法：<br>① W1 时在排课侧先落 **`ScheduleService` 接口 ＋ 占位实现（一律返回 0）**；<br>② 各主数据模块**只依赖这个接口**，不关心它是真是假；<br>③ **W4 必须把四处占位逐个替换为真实统计**，并把"**替换完成 ＋ 四个删除门禁各跑一轮回归**"写进 W4 验收点。<br>⚠️ 忘了替换的后果是**删除门禁形同虚设**（永远允许删），所以这条要盯住。 |
| 8 | 用户端导航形态 | **底部 tabBar 四个 tab：首页 / 约课 / 在约 / 我的**（沿用既有 `pages.json` 的 tabBar 配置，**不做二级页**）；约课页是**一级 tab 页**，**不需要返回箭头**。其中**「在约」与「我的」是一期空页**——不接任何接口（一期免登录、没有预约、没有会员） |
| 9 | 排课卡片要不要课程封面 | **要**：卡片增加 `courseCoverUrl`（`BR-用户端-007` 已同步补上）；详情页本来就返回 `courseCoverUrl` |
| 10 | 已取消／已结束的卡片能否点进详情 | **能点进去**，但**「立即预约」不可点**（卡片与详情页的 `bookable = false`） |
| 11 | 若依自带的「系统管理」菜单 | **完全不动**。业务菜单**另开一级目录**——既有的 `2000`「经营基础」，与「系统管理」并列；详见 §6 第 7 行 |

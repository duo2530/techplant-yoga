| 口径 | 数量 |

> `首页1/2/3.png` 是**同一页的 3 段滚动**，不是 3 个页面。

**微信原生部分为什么剔除**：
- **地图页**：微信官方文档 `wx.openLocation` 明确写明「可直接调用**微信内置地图**」，只接收 `latitude / longitude / name / address`，然后打开微信自己的地图页（[官方文档](https://developers.weixin.qq.com/miniprogram/dev/api/location/wx.openLocation.html)、[参考文章](https://cloud.tencent.com.cn/developer/article/2492121)）。截图特征完全吻合：悬浮圆形返回、底部位置卡、腾讯地图、无小程序 tabBar。
- **位置授权弹窗**：微信原生 `wx.getLocation` 授权弹窗（截图内文案「一水瑜伽 申请 / 获取你的位置信息 / 推荐附近场馆服务」）。**按用户判断，属微信端能力，不纳入本产品功能梳理。**

## 1. 一句话定位

一款**页面极少、入口极多**的**上海本地**瑜伽·普拉提约课小程序：
所有业务动作最终都收敛到「**约课页**」这一个页面完成，首页本质是**入口聚合页**；
同时它是一款**到店履约型**产品，且**深度依赖微信原生能力**（地图、收藏、转发、手机号授权、位置授权）。

## 5. 关键发现

**① 这是一个"页面极少、入口极多"的轻量小程序。**
**自研页面 11 个**，其中 4 个是 tabBar。首页有 10 个可点出口，其中 **5 个都只是把用户送到「约课页」的某个 Tab**；所有"更多/查看全部"都**没有独立的内容页**。

**② 约课页是全产品的业务枢纽。**
团课、精品课、私教课、特色课、日期选择、教练列表、预约动作**全部收敛在这一个页面**。它既是 tabBar 页（底部高亮"约课"），又带返回箭头、且**返回会回到来源页** —— 一个页面同时承担"Tab 页"和"二级页"两种角色。

**③ 约课页 4 个品类里，只有「私教课」有数据。**
团课、精品课、特色课在**不同日期下都是「暂无数据」**。**按假设 A1：默认所有门店品类能力一致，只是数据配置不同** —— 其他门店可能有数据，当前门店没有。

**④ 产品大量依赖微信原生能力，"自研成分"很低。**

| 能力 | 提供方 |
|---|---|
| 地图页 / 导航 / 打车 | 微信内置地图页（`wx.openLocation`） |
| 位置获取 | 微信位置授权（`wx.getLocation`） |
| 收藏 | 微信收藏 |
| 「更多」→ 腾讯地图 | 腾讯地图小程序 |
| 转发 / 分享 | 微信原生菜单 |
| 手机号获取 | 微信授权 |

**结论：这个产品的开发投入是"薄"的** —— 靠微信生态补齐体验，自己主要做业务流程和页面。

**⑤ 登录页是"双通道 + 协议门槛"的设计。**

```
登录页
├─ 快速登录             ← 主按钮（微信一键登录）
├─ 输入手机号登录/注册   ← 备选通道
└─ 已阅读并同意"用户协议"和"隐私政策各条款"  ← 默认【未勾选】
```

**协议勾选框默认是空的**，说明登录前有一道合规门槛。这也是「用户协议」「隐私政策」两个页面的**第二个入口**（第一个在"我的"页）。

**⑥ 首页的交互是"稀疏"的——大量区域只是展示。**
门店卡的**图片**和**门店名**点了没反应（只有地址可点）；公告栏**根本不是入口**，是**服务端数据驱动的动态滚动展示区**（有"加载中"态）。说明首页交互点很集中（就那 10 个）。

**⑦ 约教练页是一个"死页面"。**
能看教练课表（课程名/时间/教室/剩余名额），但**卡片点不动、也没有任何预约入口**。教练的能力被拆成两半：**课表在约教练页，预约在约课页私教 Tab**。用户看完课表想约，必须退回首页再走一遍"私教预约"。明显的体验断点。

**⑧ 登录拦截覆盖了预约与个人中心全链路。**
实测触发登录拦截的入口至少 **4 个**：「换店」「立即预约」「私教课教练卡」「已约」Tab。规律是**浏览不拦、履约与个人资产拦**。

**⑨ 弱网 / 飞行模式下登录拦截会失效（缺陷）。**
正常点「已约」会跳登录页，飞行模式下却直接进入「我的预约」页面。登录校验依赖接口返回、网络失败时未兜底。**已按用户判断记为缺陷，不作为产品设计依据**；需注意 **P3 / P4 / P9 的截图正取自该状态**。

**⑩ 私教课的可约资源里混入了非教练账号。**
约课页私教课 Tab 下列出"胡萝卜 / 万嘉广场店客服 / 一水双桥店"，后两个明显是**门店/客服后台账号**。属运营配置或账号命名问题。

**⑪ 体验课走的是"审核制"，不是即时预约。**
P9「我的体验课」的 4 个状态 Tab（全部 / **申请待审核** / **审核通过** / **审核拒绝**）说明体验课申请**需要人工审核**，与正式课程的"立即预约"是两套流程。

**⑫ 「申请体验」表单有完整的必填校验。**
选门店前主按钮**置灰**；选了门店后**变蓝**；数据不完整时点击，**在表单下方提示**（如"请填写手机号"）。

**⑬ 命名与落点不一致出现了两次。**

| 入口文案 | 实际落点 |
|---|---|
| 「我要打卡」（首页） | 分享海报轮播页 |
| 「我的预约」（申请体验页底部） | 我的体验课页 |

**⑭ 空态文案不统一，但比想象中更集中。**
「活动列表」「我的体验课」「消息页」「约课页」用「**暂无数据**」；「我的预约」用长文案；首页用「今日暂无可约课程」「暂无热门课程」。**"暂无数据"是主流写法，其余是例外。**

**⑮ 门店范围集中在上海，是本地化/单城市运营。**

**⑯ 消息页极简。**
只有标题 + 空态「暂无数据」，是**纯通知列表**，不承载任何操作。入口只有「我的」页左上角铃铛。

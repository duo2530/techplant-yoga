## 0. 页面计数

| 口径 | 数量 |
|---|---|
| 截图张数 | **21 张** |
| **本产品自研页面** | **15 个** |
| 微信原生页/弹窗（不计入） | **3 个**（地图页、位置授权弹窗、手机号授权弹窗） |

> 同一页面的多张截图：`首页1/2/3.png`（3 段滚动）、`登录页.png` + `快速登录.png`（快速登录页的两个状态）、`手机登录页.png` + `手机注册页.png`（**同一页的两个 Tab**）。

**微信原生部分为什么剔除**：
- **地图页**：微信官方文档 `wx.openLocation` 明确写明「可直接调用**微信内置地图**」，只接收 `latitude / longitude / name / address`（[官方文档](https://developers.weixin.qq.com/miniprogram/dev/api/location/wx.openLocation.html)、[参考文章](https://cloud.tencent.com.cn/developer/article/2492121)）。截图特征完全吻合。
- **位置授权弹窗**：`wx.getLocation` 授权弹窗。
- **手机号授权弹窗**：微信手机号快速验证弹窗。
- **按用户判断：以上均属微信端能力，不纳入本产品功能梳理。**

## 1. 一句话定位

一款**页面极少、入口极多**的**上海本地**瑜伽·普拉提约课小程序：
所有业务动作最终都收敛到「**约课页**」这一个页面完成，首页本质是**入口聚合页**；
同时它是一款**到店履约型**产品，且**深度依赖微信原生能力**。

**运营主体（来自协议页正文）**：
> **上海翼水忻河体育管理有限公司**，旗下品牌 **一水瑜伽**

## 5. 关键发现

**① 这是一个"页面极少、入口极多"的轻量小程序——但登录模块是例外。**
**自研页面 15 个**，其中 4 个是 tabBar。首页有 10 个可点出口，其中 **5 个都只是把用户送到「约课页」的某个 Tab**。

值得注意的是**结构反差**：
- 核心业务闭环（约课）只需要 **3 个页面**：首页 → 约课 → 我的预约
- 而**登录模块有 4 个页面 + 2 个协议页 = 6 个**（快速登录页、手机号登录/注册页、忘记密码页、用户协议、隐私协议）

**登录模块的页面数，是核心业务闭环的两倍。**

**② 约课页是全产品的业务枢纽。**
团课、精品课、私教课、特色课、日期选择、教练列表、预约动作**全部收敛在这一个页面**。它既是 tabBar 页（底部高亮"约课"），又带返回箭头、且**返回会回到来源页** —— 一个页面同时承担"Tab 页"和"二级页"两种角色。

**③ 登录模块是一个"闭环"，两条通道互相可达。**

```
        ┌─────────────────────────────────────────┐
        │                                         │
        ▼                                         │
   快速登录页 ⑩ ──「输入手机号登录/注册」──→ 手机号登录/注册页 ⑭
        │                                        │
        └────────「快捷登录」(左下角)────────────┘
                        │
                        └──「忘记密码？」──→ 忘记密码页 ⑮

   登录方式：① 微信手机号快速验证（主）  ② 手机号 + 密码（备）
   注册方式：手机号 + 短信验证码 + 密码
```

**四条通道没有死路**：从任一登录方式都能到另一种。

**④ 协议页是登录链路的"公共依赖"。**
「用户协议」「隐私协议」被 **3 处**引用：
- 我的页（2 个列表项）
- 快速登录页底部（协议文案）
- 手机号登录/注册页底部（协议文案，登录/注册两个 Tab 下都有）

**且所有协议勾选框默认都是未勾选的** —— 登录前有一道合规门槛。

**⑤ 产品大量依赖微信原生能力，"自研成分"很低。**

| 能力 | 提供方 |
|---|---|
| 地图页 / 导航 / 打车 | 微信内置地图页（`wx.openLocation`） |
| 位置获取 | 微信位置授权（`wx.getLocation`） |
| 手机号获取与验证 | 微信手机号快速验证 |
| 收藏 | 微信收藏 |
| 「更多」→ 腾讯地图 | 腾讯地图小程序 |
| 转发 / 分享 | 微信原生菜单 |

**结论：这个产品的开发投入是"薄"的** —— 靠微信生态补齐体验，自己主要做业务流程和页面。

**⑥ 运营主体已确认。**
协议页正文写明：**上海翼水忻河体育管理有限公司**，旗下品牌 **一水瑜伽**。结合门店全在上海，可确认为**上海本地单一主体运营的区域品牌**。两份协议更新于 **2024-09-19 / 2024-12-02**，反映上线时间不晚于 2024-09。

**⑦ 首页的交互是"稀疏"的——大量区域只是展示。**
门店卡的**图片**和**门店名**点了没反应（只有地址可点）；公告栏**根本不是入口**，是**服务端数据驱动的动态滚动展示区**（有"加载中"态）。首页交互点很集中（就那 10 个）。

**⑧ 约教练页是一个"死页面"。**
能看教练课表（课程名/时间/教室/剩余名额），但**课程卡点不动、教练相册无内容不可点、也没有任何预约入口**。教练能力被拆成两半：**课表在约教练页，预约在约课页私教 Tab**。用户看完课表想约，必须退回首页再走一遍"私教预约"。明显的体验断点。

**⑨ 登录拦截覆盖了预约与个人中心全链路。**
实测触发登录拦截的入口至少 **4 个**：「换店」「立即预约」「私教课教练卡」「已约」Tab。规律是**浏览不拦、履约与个人资产拦**。

**⑩ 弱网 / 飞行模式下登录拦截会失效（缺陷）。**
正常点「已约」会跳快速登录页，飞行模式下却直接进入「我的预约」页面。登录校验依赖接口返回、网络失败时未兜底。**已按用户判断记为缺陷**；需注意 **P3 / P4 / P9 的截图正取自该状态**。

**⑪ 私教课的可约资源里混入了非教练账号。**
约课页私教课 Tab 下列出"胡萝卜 / 万嘉广场店客服 / 一水双桥店"，后两个明显是**门店/客服后台账号**。属运营配置或账号命名问题。

**⑫ 体验课走的是"审核制"，不是即时预约。**
P9「我的体验课」的 4 个状态 Tab（全部 / **申请待审核** / **审核通过** / **审核拒绝**）说明体验课申请**需要人工审核**，与正式课程的"立即预约"是两套流程。

**⑬ 命名与落点/口径不一致共 3 处。**

| # | 入口文案 | 实际落点 / 实际标题 | 性质 |

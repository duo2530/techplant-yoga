## 0. 阅读约定

### 0.1 排序原则

本版所有清单**不再按"发现顺序"排，一律按心智模型排**：

1. **页面清单**：先 4 个 tabBar 一级页面 → **再按每个 tabBar 页面从上到下的入口顺序**，排它引出的二级页面 → **琐碎/公共模块放最后**
2. **跳转清单**：同样按**来源页面从上到下**排；同一来源内的多个入口，按**空间顺序（先上后下、先左后右）**
3. **归纳类内容**（如返回、tabBar 互通、系统能力）**统一归纳到末尾**，不散落在各页中间

### 0.2 编码规则

| 前缀 | 含义 | 英文锚点 |
|---|---|---|
| `P` | 自研页面 | **P**age |
| `V` | 待确认页面（未验证存在） | to **V**erify |
| `C` | 实测确认的跳转 | **C**onfirmed |
| `T` | 待确认的跳转 | **T**o verify |
| `N` | 实测无响应 / 非入口 | **N**o-op |
| `S` | 页内状态切换 / 页内交互（不换页） | **S**tate |
| `A` | 假设（非实测，按用户口径采纳） | **A**ssumption |

### 0.3 交付形态约定

文本、Mermaid、PlantUML

## 5. 关键发现

**① 这是一个"页面极少、入口极多"的轻量小程序——但登录模块是例外。**
**自研页面 15 个**，其中 4 个是 tabBar。首页有 10 个可点出口，其中 **5 个都只是把用户送到「约课页」的某个 Tab**。

结构反差值得注意：
- 核心业务闭环（约课）只需 **3 个页面**：首页 → 约课 → 我的预约
- **登录模块有 6 个**：快速登录页、手机号登录/注册页、忘记密码页、用户协议、隐私协议（含快登/我的两处入口）

**② 约课页是全产品的业务枢纽。**
团课、精品课、私教课、特色课、日期选择、教练列表、预约动作**全部收敛在这一个页面**。它既是 tabBar 页（底部高亮"约课"），又带返回箭头、且**返回会回到来源页** —— 一个页面同时承担"Tab 页"和"二级页"两种角色。

**③ 登录模块是一个"闭环"，两条通道互相可达。**

```
        ┌─────────────────────────────────────────┐
        │                                         │
        ▼                                         │
   快速登录页 P13 ──「输入手机号登录/注册」──→ 手机号登录/注册页 P14
        │                                        │
        └────────「快捷登录」(左下角)────────────┘
                        │
                        └──「忘记密码？」──→ 忘记密码页 P15

   登录方式：① 微信手机号快速验证（主）  ② 手机号 + 密码（备）
   注册方式：手机号 + 短信验证码 + 密码
```

**四条通道没有死路。**

**④ 登录成功后按 `navigateBack` 回来源页（用户约定的设计标准）。**
即：**哪个页面触发登录，登录成功后就回到哪个页面**。所以约课页触发登录 → 登录后回约课页；首页「换店」触发 → 回首页。这解释了为什么登录页需要「返回」按钮 —— 它是被推入的页面。

**⑤ 协议页是登录链路的"公共依赖"。**
「用户协议」「隐私协议」被 **3 处**引用：我的页、快速登录页底部、手机号登录/注册页底部。**且所有协议勾选框默认都是未勾选的** —— 登录前有一道合规门槛。

**⑥ 产品大量依赖微信原生能力，"自研成分"很低。**

| 能力 | 提供方 |
|---|---|
| 地图页 / 导航 / 打车 | 微信内置地图页（`wx.openLocation`） |
| 位置获取 | 微信位置授权（`wx.getLocation`） |
| 手机号获取与验证 | 微信手机号快速验证 |
| 收藏 | 微信收藏 |
| 「更多」→ 腾讯地图 | 腾讯地图小程序 |
| 转发 / 分享 | 微信原生菜单 |

**⑦ 运营主体已确认。**
协议页正文写明：**上海翼水忻河体育管理有限公司**，旗下品牌 **一水瑜伽**。结合门店全在上海，可确认为**上海本地单一主体运营的区域品牌**。两份协议更新于 **2024-09-19 / 2024-12-02**，反映上线时间不晚于 2024-09。

**⑧ 首页的交互是"稀疏"的——大量区域只是展示。**
门店卡的**图片**和**门店名**点了没反应（只有换店和地址可点）；公告栏**根本不是入口**，是**服务端数据驱动的动态滚动展示区**（有"加载中"态）。

**⑨ 约教练页是一个"死页面"。**
能看教练课表，但**课程卡点不动、教练相册无内容不可点、也没有任何预约入口**。教练能力被拆成两半：**课表在约教练页，预约在约课页私教 Tab**。用户看完课表想约，必须退回首页再走一遍"私教预约"。明显的体验断点。

**⑩ 登录拦截覆盖了预约与个人中心全链路。**
实测触发登录拦截的入口至少 **4 个**：「换店」「立即预约」「私教课教练卡」「已约」Tab。规律是**浏览不拦、履约与个人资产拦**。

**⑪ 弱网 / 飞行模式下登录拦截会失效（缺陷）。**
正常点「已约」会跳快速登录页，飞行模式下却直接进入「我的预约」页面。登录校验依赖接口返回、网络失败时未兜底。**已按用户判断记为缺陷**；需注意 **P3 / P4 / P6 的截图正取自该状态**。

**⑫ 私教课的可约资源里混入了非教练账号。**
约课页私教课 Tab 下列出"胡萝卜 / 万嘉广场店客服 / 一水双桥店"，后两个明显是**门店/客服后台账号**。

**⑬ 体验课走的是"审核制"，不是即时预约。**
P6 的 4 个状态 Tab（全部 / **申请待审核** / **审核通过** / **审核拒绝**）说明体验课申请**需要人工审核**，与正式课程的"立即预约"是两套流程。

**⑭ 「我要打卡」的分享海报没有动态生成能力。**
右下角小程序码是**海报图片自带**的（换图即消失），说明海报是**预先做好的静态图片**，页面只做了「轮播 + 保存/转发」。
**因此它不具备"动态生成带参二维码"的分享裂变能力 —— 无法区分不同分享者的来源。**

**⑮ 命名与落点/口径不一致共 3 处。**

| # | 入口文案 | 实际落点 / 实际标题 |
|---|---|---|
| 1 | 「我要打卡」（首页） | 分享海报轮播页 |
| 2 | 「我的预约」（申请体验页底部） | **我的体验课**页 |
| 3 | 「**隐私政策**」（我的页 / 两个登录页） | 页面标题实为「**隐私协议**」（协议正文内又写"《用户隐私政策》"） |

**⑯ 空态文案以「暂无数据」为主流。**
「活动列表」「我的体验课」「消息页」「约课页」都用「**暂无数据**」；例外：「我的预约」用长文案；首页用「今日暂无可约课程」「暂无热门课程」。

**⑰ 按钮的"置灰 → 可点"是一致的交互规范（观察 3 处）。**
申请体验页（选门店前）、忘记密码页（未填时）、约课页预约按钮（未登录时暗色）。**这是一致规范，不是缺陷。**

# MVP 业务流程图

**版本：v0.4**（2026-09-29）
**适用范围：** 门店、课程、教练、排班、会员、会员卡和预约的 MVP 闭环

## 1. 业务说明

本流程描述一次完整的 MVP 预约闭环：管理端先为排班选择门店、课程、教练并设置开始时间、结束时间和总容量；游客浏览门店和课程排班，登录后成为初始等级为 0 的会员。会员首次没有可用卡时，由门店管理员先开卡并激活；会员卡激活后可以持续使用，后续预约不再需要管理员介入。

预约时，系统先根据课种筛选已激活且可用的会员卡：团课和精品课可以使用普拉提次数卡或适用的期限卡，私教课只能使用私教次数卡。只有一张候选卡时自动选中；有多张候选卡时展示全部候选卡并默认选中列表第一张，会员可以切换。

同一会员对同一排班只能生成一条预约记录，但一条记录可以填写两人或多人同行的预约人数。提交预约后，系统通过 MySQL 行级锁锁定排班记录，按预约人数校验剩余容量，并在同一事务内完成预约创建、次数卡按预约人数扣减、已预约人数增加；期限卡只校验有效期，预约记录本身代表本次使用。

## 2. 业务流程图

```plantuml
@startuml
title 瑜伽普拉提 MVP 业务流程图

|平台管理员/门店管理员|
start
:选择排班门店、课程和授课教练;
:设置开始时间、结束时间和总容量;
:保存排班;

note right
平台管理员与门店管理员先作为页面角色
菜单、按钮和数据权限本期暂不设计
店长、前台等细分角色本期暂不拆分
end note

|游客/会员|
:进入首页;
:浏览门店、课程及当天排班;
if (是否预约课程？) then (是)
  if (是否已登录？) then (否)
    :登录或注册;
    :建立会员身份，会员等级初始化为 0;
  endif

  :选择课程排班;

  |会员卡管理|
  :按课种、激活状态、剩余次数或有效期筛选会员卡;
  if (存在可用会员卡？) then (否)
    |门店管理员|
    :首次为会员开卡;
    :新增会员卡，初始状态为“未激活”;
    :点击激活并记录激活时间;
    if (期限卡？) then (是)
      :月卡设置 30 个自然日有效期;
      :年卡设置 365 天有效期;
    endif
    |会员卡管理|
    :重新筛选已激活且适用的会员卡;
  endif

  |游客/会员|
  if (候选会员卡是否多于一张？) then (是)
    :展示全部候选卡;
    :默认选中列表第一张;
    :确认或切换会员卡;
  else (否)
    :自动选中唯一候选卡;
  endif
  :填写预约人数;
  :点击“立即预约”;

  |预约管理|
  :开启事务并锁定排班记录;
  :校验同一会员对同一排班没有其他预约记录;
  :按预约人数校验剩余容量;
  :校验所选会员卡仍然可用且适用当前课程;

  if (预约条件满足？) then (是)
    if (次数卡？) then (是)
      :按预约人数扣减次数;
    else (期限卡)
      :只校验有效期;
    endif
    :生成一条“已预约”记录并保存预约人数;
    :按预约人数增加排班已预约人数;
    if (事务处理成功？) then (是)
      :提交事务;
      |游客/会员|
      :查看预约成功结果;
    else (否)
      |预约管理|
      :整体回滚预约、会员卡和人数变更;
      |游客/会员|
      :查看预约失败原因;
    endif
  else (否)
    :不写入业务变更并释放排班锁;
    |游客/会员|
    :查看不可预约原因;
  endif

  if (预约是否成功？) then (是)
    :进入“我的预约课”;
    :查看已预约、已取消、已签到分类;

    if (发起取消预约？) then (是)
      if (距离开课时间不少于 2 小时？) then (是)
        :选择取消原因并提交;
        |预约管理|
        :更新预约状态为“已取消”;
        if (原预约使用次数卡？) then (是)
          :按预约人数返还次数;
        else (期限卡)
          :不处理会员卡次数;
        endif
        :按预约人数减少排班已预约人数;
        |游客/会员|
        :查看取消结果;
      else (否)
        :提示开课前 2 小时内不可取消;
        note right
        门店管理员代取消也不能突破该限制
        MVP 不支持门店自定义取消时限
        end note
      endif
    endif

    |门店管理员|
    if (预约仍为“已预约”且会员到店？) then (是)
      :在预约管理中手工签到;
      |预约管理|
      :将“已预约”更新为“已签到”;
    endif
  endif
else (否)
  :继续浏览门店、课程和排班;
endif
stop
@enduml
```

## 3. 已确认规则

- 只有已激活、未过期或次数充足，并且适用当前课种的会员卡才能参与选择。
- 团课和精品课可以使用普拉提次数卡或适用的期限卡；私教课只能使用私教次数卡。
- 多张候选卡全部展示并默认选中列表第一张，会员可以切换。
- 同一会员对同一排班只能有一条预约记录，但预约记录可以填写多人同行的预约人数。
- 次数卡按预约人数扣减，例如预约两人扣两次；期限卡只校验有效期，预约记录本身代表本次使用。
- 预约使用 MySQL 排班记录行级锁和事务控制容量，必须防止并发超卖。
- 取消次数卡预约时按预约人数返还次数；取消期限卡预约时不处理会员卡次数。
- 会员和门店管理员均不能在开课前两小时内取消预约；MVP 不支持门店单独配置取消时限。
- 门店管理员在预约管理中手工签到；支付宝刷脸等自动签到方式不纳入 MVP。
- 取消原因包括“临时有事”“请假”“身体不适”。
- 排班修改或取消后，通过短信和站内信通知受影响会员。
- 排班取消后，关联的“已预约”记录自动变为“已取消”，取消来源为“排班取消”；次数卡按预约人数立即返还，期限卡不处理次数。
- 短信和站内信只尝试发送一次，发送失败不重试。
- 平台管理员、门店管理员及店长、前台等细分权限本期暂不设计，先完成管理页面。

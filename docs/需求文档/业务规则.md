# 业务规则

**文档版本：v2.1（重置版）**（2026-10-01）
**适用范围：** 一期 —— 用户端（免登录浏览）与管理端（门店、教室、教练、课程、排课）。

**用途：** 只写「业务上必须成立什么」，不写实现方式。

## 依据来源（都是需求依据，没有「唯一」）

**本文不是唯一权威。** 本项目有三个平行的需求依据，都具备权威性：

| 来源 | 位置 | 说明 |
|---|---|---|
| 业务规则（本文件） | `docs/需求文档/业务规则.md` | 本次重构后确认的业务口径：门店、教室、教练、课程、排课 |
| **真实产品证据** | `docs/产品分析/` | **对标真实 App 的用户端实测截图**（`用户端小程序截图/`）、`用户端页面与对象.md`、`用户端页面与跳转梳理.md`——**用户端界面、信息结构与页面跳转的第一手证据** |
| 功能清单与结构图 | `docs/需求文档/用户端/`、`docs/需求文档/管理端/` | 功能范围来源 |

**冲突处理：** 三者出现不一致时，**不预设优先级，回到讨论确认**；以当次讨论确认的结论为准，并把结论回写进相关文档。**任何文档都不能覆盖当次讨论的结论。**

**分工：** 本文件只写业务口径，不描述界面；用户端的界面与交互细节以 `docs/产品分析/` 的截图与跳转梳理为准。

## 使用说明

| 项 | 说明 |
|---|---|
| 编号 | `BR-<模块>-<三位序号>`（如 `BR-排课-004`） |
| 类型 | `资格` / `口径` / `唯一性` / `限额` / `时效` / `状态流转` / `计算` / `边界例外` / `范围` |
| 状态 | 本版所有规则均为**已确认**，可直接开发 |
| 阈值 | 含数值阈值的规则标注 `（参数：名称 = 当前取值）`，调整数值只改这一处 |
| 不写什么 | **不写**字段名、表名、接口路径、错误码、索引、分页这类实现细节——它们属详细设计 |
| 本版说明 | 本版为**重置版**：范围收敛为「两个端、一期只到浏览」，**编号从 001 重新开始**；不登记历史废止条目，也不保留「待确认」「已关闭」的堆积 |

# 0、全局规则

| 编号 | 规则 | 类型 | 状态 |
|---|---|---|---|
| BR-全局-001 | 一期只有**两个端**：**用户端**与**管理端**。 | 范围 | 已确认 |

| BR-全局-003 | 一期只有**平台管理员**一个管理角色，可读写全部数据；不设门店管理员，不设菜单权限、按钮权限与数据范围。 | 范围 | 已确认 |
| BR-全局-004 | **管理端必须登录**后才能访问，登录方式为**用户名 ＋ 密码**。 | 资格 | 已确认 |
| BR-全局-005 | 一期明确**不纳入**：用户端登录与账号、会员、会员卡、预约与取消预约、签到、通知与短信、**私教排课与私教预约**（课种枚举仍保留「私教课」）、教练端（教练登录、营业时间登记、取消私教排班）、体验课、优惠券、积分、礼包、合同、体测、公告、消息、活动、候补排队、角色与数据权限、统计看板、最低开课人数的自动取消、**门店经营类型**（一期只做直营连锁，不建该字段）。 | 范围 | 已确认 |
| BR-全局-006 | 主体不存在或已删除时，查询详情、修改、状态变更与删除一律拒绝并提示不存在。 | 资格 | 已确认 |
| BR-全局-007 | 引用检查类门禁在校验不通过、**或校验本身无法完成**时一律拒绝，不得降级放行。 | 边界例外 | 已确认 |
| BR-全局-008 | 重复设置当前已生效的同一状态时，一律按成功处理（幂等）。 | 边界例外 | 已确认 |
| BR-全局-009 | **删除门禁统一口径**：门店、教室、教练、课程存在**未结束、且状态为「待上架」或「已上架」**的排课引用时，一律拒绝删除并提示被引用的排课数量；**已取消的排课、以及时间已过（已结束）的排课不阻塞删除**。删除后这些历史排课上的对应对象显示为空，管理端做空值兜底。 | 状态流转 | 已确认 |
| BR-全局-010 | 用户端首次进入默认选中门店列表中的**第一家**门店；用户切换门店后由客户端记住当前门店，不登录、不落服务端。 | 口径 | 已确认 |

# 1、门店

| 编号 | 规则 | 类型 | 状态 |
|---|---|---|---|
| BR-门店-001 | 门店是用户端浏览与排课的**服务地点**；门店下设教室，排课归属门店。用户端切换门店后只展示该门店的排课。 | 范围 | 已确认 |
| BR-门店-002 | 用户端门店列表只返回**未删除**的门店；**支持按「所在区域」与「名称／地址关键字」筛选**；无门店时显示空态。 | 资格 | 已确认 |
| BR-门店-003 | 门店名称必须**唯一，不允许重名**（修改时排除自身）。 | 唯一性 | 已确认 |
| BR-门店-004 | 门店类型为**固定枚举：主力店、精品店**。 | 口径 | 已确认 |
| BR-门店-005 | 门店的**所在区域**保存**上海市市辖区的行政区划代码**（6 位）；取值合法性与区名翻译**都由字典表承担**（`sys_dict_data`，`dict_type = store_region`，共 16 条）。 | 口径 | 已确认 |
| BR-门店-006 | 门店营业时间只保存**一段固定展示文本**：不拆分时段，不做跨日、节假日与特殊营业日规则。 | 范围 | 已确认 |
| BR-门店-007 | 门店字段只有：门店名称、门店类型、所在区域 code、联系电话、营业时间、地址、门店图片（**单图**，不建多图）。**不设「联系人」**。 | 范围 | 已确认 |
| BR-门店-008 | 门店**没有启用／停用状态**：只提供门店的增、删、查、改，不提供状态维护。 | 范围 | 已确认 |
| BR-门店-009 | 门店删除为**物理删除**；须先过 `BR-全局-009` 的删除门禁，且**名下有教室时同样拒绝删除**。 | 状态流转 | 已确认 |
| BR-门店-010 | 门店已被排课引用时，仍必须允许编辑门店资料（编辑不加引用门禁）。 | 边界例外 | 已确认 |

| BR-课程-004 | 课程难度以 **1~5 星**表达（参数：难度范围 = 1~5）。 | 限额 | 已确认 |
| BR-课程-005 | 课程封面**只保留单图**，不建课程多图。 | 范围 | 已确认 |
| BR-课程-006 | 课程字段只有：课程名称、课种、课程封面、课程介绍、课程难度。 | 范围 | 已确认 |
| BR-课程-007 | 课程**没有启用／停用状态**：只提供课程的新增、删除、查询与修改。 | 范围 | 已确认 |
| BR-课程-008 | 课程可删除，为**物理删除**；须先过 `BR-全局-009` 的删除门禁。 | 状态流转 | 已确认 |

| BR-课程-010 | 一期**不设**课程「展示排序」字段，用户端没有首页热门区。 | 范围 | 已确认 |

# 5、排课

| 编号 | 规则 | 类型 | 状态 |
|---|---|---|---|
| BR-排课-001 | 排课必须指定**门店、课程、教练、教室**四者，并设置**日期、开始时间、结束时间、最大人数、最低开课人数**。 | 资格 | 已确认 |
| BR-排课-002 | 开始时间必须早于结束时间；排课**不跨自然日**——日期与当天的起止时刻共同表达一次上课时段。 | 计算 | 已确认 |
| BR-排课-003 | 最大人数必须**大于 0**（参数：最大人数下限 = 1）。 | 限额 | 已确认 |
| BR-排课-004 | 最低开课人数必须**不小于 1**、且**不大于最大人数**（参数：最低开课人数默认值 = 2）。 | 限额 | 已确认 |
| BR-排课-005 | 一期**不做**「不足最低开课人数自动取消」：最低开课人数只做录入、范围校验与用户端展示，**不触发任何自动行为，也不设定时任务**。 | 范围 | 已确认 |
| BR-排课-006 | 排课的门店必须存在且未删除；课程必须存在且未删除；教练必须存在且未删除；教室必须存在，且其归属门店与排课门店一致。 | 资格 | 已确认 |
| BR-排课-007 | 同一门店 ＋ 同一课程 ＋ **完全相同的日期与起止时间**不允许重复排课；时间重叠但起止时刻不同的本版放行。 | 唯一性 | 已确认 |
| BR-排课-008 | **同一教练任意两节排课的时间不得重叠**（按日期与起止时刻构成的时间区间判定）；一旦重叠即**拒绝保存**，不做「提示后放行」。 | 资格 | 已确认 |
| BR-排课-009 | 排课只能排**今天起 14 天内**（含今天）（参数：排课窗口 = 14 天）。 | 时效 | 已确认 |
| BR-排课-010 | 排课的落库状态只有三个值：**待上架、已上架、已取消**。「已结束」**不落库**，由「结束时间不晚于当前时间」推导。 | 状态流转 | 已确认 |
| BR-排课-011 | 新增排课默认状态为**待上架**——此时用户端看不到它。 | 状态流转 | 已确认 |
| BR-排课-012 | 状态流转只有三条：**待上架 →（上架）→ 已上架**；**已上架 →（下架）→ 待上架**；**已上架 →（取消）→ 已取消**。没有「已下架」这个状态。**已取消是终态**，不可再流转；派生的**已结束**同样是终态。 | 状态流转 | 已确认 |
| BR-排课-013 | **只有「待上架」的排课可编辑**；**已上架、已取消、已结束都不可编辑**——要改已上架的排课，必须**先下架**（回到待上架）再改，改完重新上架。 | 状态流转 | 已确认 |
| BR-排课-014 | 排课可**物理删除**，但只允许删除**待上架**的排课；**已上架**须先下架（回到待上架）后才能删除；**已取消**与**已结束**的排课**不得删除**。 | 状态流转 | 已确认 |
| BR-排课-015 | 用户端展示**除「待上架」以外**的排课：**已上架（含已结束）与已取消都可被用户看到**，只有**待上架不展示**。 | 资格 | 已确认 |
| BR-排课-016 | 用户端查询必须固定施加的过滤条件：**未删除、状态不等于「待上架」、门店等于当前所选门店**；日期区间由日期条给出。 | 资格 | 已确认 |
| BR-排课-017 | 用户端按**门店 ＋ 日期**查询排课；**日期条件按排课保存的日期字段判定**（不是用开始时间与结束时间拼条件）；日期范围为**今天起 14 天**（含今天），页面提供日期条并**默认选中今天**（参数：可选天数 = 14）。 | 时效 | 已确认 |
| BR-排课-018 | 剩余名额 = 最大人数 − 已预约人数，**下限为 0**；一期不提供预约，已预约人数恒为 0，剩余名额恒等于最大人数。 | 计算 | 已确认 |
| BR-排课-019 | 「已预约人数」字段一期**保留并固定为 0**，只允许预约模块维护（一期无该模块）；管理端表单中该字段**只读**。 | 唯一性 | 已确认 |
| BR-排课-020 | 管理端排课列表须展示**状态**并支持按状态筛选；**用户端排课卡片也须展示状态**，至少能区分「可约／已结束／已取消」，否则已取消的课会被误认为正常。 | 口径 | 已确认 |
| BR-排课-021 | 排课必须保存所选课程的**课种快照**——由服务端从课程取，**不接受客户端提交**；**更换排课课程时刷新快照**，这是快照的**唯一刷新点**。用户端**课种 Tab 筛选**与后续预约的卡适用范围校验，**一律以排课快照为准，不回读课程**。 | 口径 | 已确认 |
| BR-排课-022 | 排课必须保存**独立的日期字段**（当天上课日期，由开始时间推导、**服务端写入、不接受客户端提交**）；用户端日期条与管理端日期区间筛选**一律按该日期字段判定**，不再用开始时间与结束时间拼条件。 | 口径 | 已确认 |

# 6、用户端页面

|---|---|---|---|

| BR-用户端-002 | **门店切换在「首页」完成**；一期**不做登录拦截**，未登录即可查看门店列表并切换门店。 | 资格 | 已确认 |

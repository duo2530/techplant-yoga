# 功能清单汇总（一期）

**文档版本：v2.0（重置版）**（2026-10-01）

**用途：** 把**一期**要做的事汇总成一张表，回答「一期做哪些功能、每项到什么程度、优先级怎么排」。

## 依据来源（三个平行依据，没有「唯一权威」）

| 来源 | 位置 | 说明 |
|---|---|---|
| 业务规则 | [`业务规则.md`](业务规则.md) | **业务口径的依据**；本文只引用编号，不复制条文 |
| **真实产品证据** | `docs/产品分析/` | **对标真实 App 的用户端实测截图**、`用户端页面与对象.md`、`用户端页面与跳转梳理.md`——用户端界面与跳转的第一手证据 |
| 分端功能清单与结构图 | `docs/需求文档/用户端/`、`docs/需求文档/管理端/` | 功能范围来源（**由人工手工维护**） |

**冲突处理：** 三者不一致时**不预设优先级，回到讨论确认**，以当次结论为准并回写文档。

> ⚠️ `docs/概要设计/`、`docs/详细设计/`、`docs/项目管理/` 描述的是**旧设计**（含会员、会员卡、预约、数据范围等已不在本期范围的能力），**不作为本文依据**。

## 维护口径

1. **一行一个功能**，按业务模块分组；范围外的能力集中列在 §3，不进正文表格。
2. **优先级**：`P0` 本期成立条件（缺了这期就不成立）；`P1` 本期应做（缺少会明显影响体验，可在本期后段补齐）；`P2` 本期加分项（可顺延）。
3. 编号 `F-<模块>-NN`，本版为重置版，编号**从 01 重新开始**。

## 1. 一期总览

| 项 | 内容 |
|---|---|
| **目标** | **能看**：管理端把门店、教室、教练、课程、排课维护起来，用户端**免登录**能按门店看到排课并进入课程详情 |
| **验收口径** | 管理端能建好门店与教室、平台级教练与课程，并排出一节**已上架**的排课；用户**不登录**即可在首页切换门店、在约课页看到这节排课、点进去看到课程资料与本次上课信息；点「立即预约」提示**敬请期待** |
| **覆盖用例** | 用户端 UC-001 ~ UC-003；管理端 UC-004 ~ UC-009（共 9 条，见 [`docs/需求分析/用例总览.md`](../需求分析/用例总览.md)） |
| **两个端** | **用户端**（微信小程序，**免登录**）、**管理端**（**平台管理员**，用户名 ＋ 密码登录） |
| **五个对象** | 门店、教室、教练（平台级）、课程（平台级）、排课 |

**一期项数：51 项**（用户端 12 ＋ 管理端 39）。

| 编号 | 功能 | 对应用例 | 期次 | 优先级 | 说明 |

> 「已结束」**不落库**，由结束时间推导；这是终态，不可编辑、不可删除。

## 4. 开工前的前置事项（**5 条全部已定**）

| # | 事项 | **结论** |
|---|---|---|
| 1 | 管理端登录账号的来源 | **沿用脚手架自带账号体系**（`admin / admin123`）；**改密本期不做**，上线前统一处理 |
| 2 | 门店图片与教练相册的存储与上传方式 | **用若依自带的 `POST /common/upload`，存本地文件、库里只存 URL**；门店图片／教练头像／教练相册／课程封面四处复用同一套 |
| 3 | 上海市 16 个市辖区的取值 | **存行政区划 code（6 位）＋ 字典 `store_region` 翻译**；16 条字典由 SQL 种子写入，**上线前再逐条校验一次** |
| 4 | 「已预约人数」字段是否先建 | **先建并固定为 0**（用户端要显示"剩余名额"，二期接预约时不必改表） |
| 5 | 「已结束」的判定口径落在哪一层 | **在 service 层判定**（返回 controller 前一次判定，`结束时间 <= 当前时间`）；**唯一例外**是删除门禁的 count 查询把条件写在 SQL 里 |

> 完整的 7 条口径（含"旧代码就地改造""旧页面保留不删除""删除门禁占位实现 W4 必须替换"）见 [`../项目管理/一期开发路线图.md`](../项目管理/一期开发路线图.md) §8。

# 一水·瑜伽普拉提 · 高保真原型

依据 21 张真机截图复刻的 HTML 原型。

## 怎么看

双击 **`index.html`**，用浏览器打开即可。所有页面平铺在一页里，每张卡片右上角有「单独打开 ↗」可以全屏看。

> 建议用 Chrome / Edge。**不需要联网**（Tailwind 已本地化到 `assets/tailwind.js`）。

## 画布

源截图统一 **1170×2532 @3x** → 逻辑画布 **390×844**。所有页面都是这个尺寸，`.phone` 容器正好铺满。

## 两个关键做法

**1. 色值是实测的，不是估计的。**
用像素采样从截图里取出真实色值：主色 `#609CE9`、登录按钮蓝 `#87C7F6`、页面灰底 `#F7F9FC`、门店卡片 `#E2E0DB`、微信绿 `#07C160`。

**2. 照片用「雪碧图法」，不裁图、不改动原文件。**
直接把 `docs/需求文档/用户端/用户端小程序截图/` 里的原图当雪碧图，用 `background-size: 390px auto` + `background-position` 切出需要的区域：

```css
/* 显示源图 y=276..770px 这一段 */
width:390px; height:165px;
background-image:url('../需求文档/用户端/用户端小程序截图/首页1.png');
background-size:390px auto;
background-position:0 -92px;   /* -276/3 */
```

换算公式：**逻辑值 = 源图像素 ÷ 3**。可用的照片区坐标见 `规格/色带分析.txt`。
好处是**原始截图一个字节都没动**，而且照片是真实的、不是色块占位。

## 重新生成对比图

```powershell
pwsh -NoProfile -File .\docs\原型\_工具\渲染对比.ps1
```

会用 headless Chrome 把每个页面渲染出来，和原始截图拼成**左右对比图**（左=真机原截图，右=HTML 渲染），输出到 `_工具/对比/`。

单页：`pwsh -NoProfile -File ".\docs\原型\_工具\渲染对比.ps1" -Only home.html`

> **注意 `?shot=1`**：脚本会自动给 URL 加上这个参数。headless 浏览器的布局视口固定 526px、**不随 `--window-size` 变化**，不加这个参数会让 390px 的手机壳被居中、截图左右各切掉约 60px。共享的 `tokens.js` 检测到该参数会给 `<html>` 加 `.shot`，`app.css` 里对应规则把手机壳 `position:fixed` 贴到左上角。

## 实测结论（做设计/需求对齐时直接用）

这些都是**像素采样量出来的**，不是估的。完整版见 `docs/产品分析/页面与跳转梳理.md` 的 §8。

**底部 TabBar**

- 四项：**首页 / 约课 / 已约 / 我的**（页面标题是「我的预约」，但 Tab 文案是「已约」）
- **选中项：图标变蓝 `#4799EF` 且变成实心；文字始终是灰色 `#717579`**（不跟着变蓝）
- 占位：顶 764pt，图标 768..785pt，文字 793..803pt
- 未选中图标 `#C7C7C7`/`#D3D3D3`，未选中文字 `#666666`

**导航栏**

- 标题用**品牌名**而不是页面名：首页 `一水·瑜伽普拉提`（左对齐，前置书法「一」Logo），约课/我的 都是 `一水瑜伽`（居中）
- 左侧控件**每页形态不同**：`‹ 返回`（申请体验/约教练/我的体验课）／ `‹`（消息/活动列表）／ 灰色胶囊「‹ ｜ ⌂」（协议页、登录页）
- ⚠️ 判断这里有什么时**不能只用深色阈值** —— 淡化态控件的填充是 `#D9D9D9`、图标是白色，深色阈值会系统性漏掉（本项目因此得出过一次错误结论）

**其他**

- 画布：源截图 **1170×2532**（iPhone 6.1" @3x）→ 逻辑 **390×844**
- 约课页顶部有浅蓝竖向渐变头部：`#BAE6FC`(80pt) → `#D2EEFD`(146pt) → 148pt 转白
- 约课页品类 Tab 选中态：饱和蓝 `#609AE9` 圆角块（47×8pt，两端全圆角）压在标签文字上
- **微信位置授权弹窗是「底部弹层」**（不是居中弹窗），背后是被 50% 黑遮罩压暗的首页
- 首页 Banner **不是满宽**（左右各 13pt），门店卡片实测 212pt 宽、填充 `#E2E0DB`

## 关于验证报告里的 MAD 数字（**读之前先看这条**）

`_工具/对比报告.md` 里的 MAD（平均绝对差）**被状态栏系统性放大了**。

以 `booking.html` 为例，整页 MAD = 9.30，但拆开看：

| 区段 | MAD |
|---|---|
| y=0..44（状态栏） | **37.19** |
| y=44..844（其余全部） | **7.77** |

也就是说**约 76% 的差异只来自状态栏**——真机截图是「11:35 + 真机信号图标」，而原型统一用「9:41 + 标准图标」（这是刻意统一的，见下表）。

**读报告时请把状态栏区段排除**，或者直接看报告里给的「最差区段」定位，那个才是有意义的指标。

## 已知偏差（如实列出）

整体精度在 **±3pt** 内（逐像素比对），以下是有意保留或无法消除的差异：

| 项 | 情况 |
|---|---|
| 状态栏时间/图标 | 统一用 `9:41` + 标准图标，截图是 11:33/13:22 等 —— 刻意统一 |
| 字体 | Windows 渲染用 Microsoft YaHei，真机是苹方 PingFang SC，字形与每行字数略有差异 |
| 导航栏固定区高度 | 骨架 chrome 88pt vs 截图 91pt，内容区整体上移约 3–4px |
| 首页房子 TabBar 图标 | 填充密度 63% vs 真机 81.5%（屋顶坡度差异，21px 下视觉可接受） |
| 首页蓝色渐变按钮 | 原图疑似一条对角渐变，按每张卡角点取样近似 —— 全页最大的配色近似 |
| 小图标 | 未切图的图标（票券、漏斗、手机、文档等）为手绘 SVG 近似，尺寸颜色按实测 |
| 空态插画 | 消息页、活动列表页的插画为手绘 SVG 近似（原图很小很淡） |
| 约教练页天空 | 用 CSS 渐变替代照片（原图该区域右侧有空白，直接当雪碧图会串位），波纹纹理丢失 |
| 登录页选中 Tab 文字色 | 真机两张截图**自相矛盾**（`#78909C` vs `#FFFFFF`），按各自截图分别还原 |
| 协议页正文换行 | 每行比真机少约 1 字（字体差异），滚动内容多 1–2 行 |

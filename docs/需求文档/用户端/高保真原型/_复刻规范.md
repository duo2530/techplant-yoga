## 5. 图片：雪碧图法（**重要**）

不要裁图、不要生成图片文件。**直接用原截图当雪碧图**，通过 `background-position` 切出需要的照片区域。

```css
/* 显示源图 y=276..770px 这一段 */
width:390px; height:165px;              /* 高度 = (770-276)/3 */
background-image:url('../需求文档/用户端/用户端小程序截图/首页1.png');
background-size:390px auto;              /* 固定 390 宽，等比缩放 1/3 */
background-position:0 -92px;             /* y = -276/3 */
```

- 换算公式：**逻辑值 = 源图像素 ÷ 3**。
- 可用坐标：见 **`docs/原型/规格/色带分析.txt`**（每张图的纯色区/照片区/混合区的精确 y 范围）。
- 挑照片区时**必须避开文字和卡片**，否则会切进 UI。

### ⚠️ 切片偏移必须用**实测绝对坐标**，不要自己算居中

**血的教训**：给一个 138px 宽的精灵盒做"居中"时，如果按容器宽的差值手算 `-107px`，会因为精灵盒实际是 138px 而被推到右边缘、**右侧被容器裁掉**（本项目在 `my-bookings` 的插画上真的发生过，且目视不易发现，因为被切的恰好是浅灰渐变）。

- ✅ **正确做法**：量出这个元素墨迹的**绝对逻辑坐标**，直接写进去。
  例：源图插画墨迹 x=156..234pt → 精灵盒从 154 起 → **`background-position:-154px`**。
- ❌ **不要用 `50%` 做水平居中**：`background-size:390px` 时 `50%` 会被解释为 `(390-138)/2 = 126`，仍然右移被裁。
- ✅ 切完**必须做水平方向的像素比对**（不只是垂直方向）。

## 6. 每个页面的执行步骤

1. **先看截图**：用 `read_image` 直接把截图读进上下文（比 `vision` 分辨率更高，且不依赖外部 API）。要看细节就**裁出局部再放大 2~4 倍**读。
2. **再查色带**：打开 `docs/原型/规格/色带分析.txt`，找到你这张图那一段，确定照片区的 y 坐标。
3. **写 HTML**：按 §3 骨架实现。
4. **渲染自检**（必做）：
   ```powershell
   pwsh -NoProfile -File "docs\原型\_工具\渲染对比.ps1" -Only 你的页.html
   ```
   `?shot=1` 由脚本自动加。然后用 `read_image` 读 `_工具/对比/你的页.png`（左=真机、右=渲染）逐项比对。
5. **收尾自检**：文案逐字一致；固定区样式一致；照片没切到文字；一级页有 TabBar、二级页没有；390×844 内可滚动不溢出。

## 10. ⚠️ 环境坑：页面必须放在 `docs/原型/` 根目录

页面里写的是**相对路径** `assets/tailwind.js`。只有把 HTML 放在 `docs/原型/` 根目录，这个路径才解析得到。

**如果放进 `_工具/` 之类的子目录**：`assets/tailwind.js` 404 → **Tailwind 一条规则都不生成**（实测 `typeof window.tailwind === 'undefined'`、`cssRules.length === 0`），页面只剩 `app.css` 的外壳，所有 `flex` / `h-[..]` / `mt-[..]` 全部失效、卡片高度全错。

本项目有代理因此在一个"假页面"上量了好几轮才发现。**不要把待测 HTML 写进 `_工具/`。**

## 11. 渲染自检原理（为什么必须加 `?shot=1`）

headless Chrome 的**布局视口固定 526px，不随 `--window-size` 变化**。`body` 里的居中会让 390px 的手机壳偏移到 x≈68，而截图只有 390px 宽 → **左右各被切掉约 60px**。

共享 `tokens.js` 检测到 URL 里的 `shot` 参数会给 `<html>` 加 `.shot`，`app.css` 里对应规则把手机壳 `position:fixed` 贴到左上角，得到精确的 1:1 截图。`渲染对比.ps1` 会自动加这个参数。

## 1.3 数据库物理模型

### 1.3.1 建表语句

```sql
CREATE TABLE `t_schedule` (
  `id`             bigint unsigned NOT NULL COMMENT '排课ID',
  `store_id`       bigint unsigned NOT NULL COMMENT '门店ID',
  `course_id`      bigint unsigned NOT NULL COMMENT '课程ID',
  `course_type`    tinyint      NOT NULL COMMENT '课种快照：1团课 2精品课 3私教课 4特色课',
  `coach_id`       bigint unsigned NOT NULL COMMENT '教练ID',
  `classroom_id`   bigint unsigned NOT NULL COMMENT '教室ID',
  `schedule_date`  date NOT NULL COMMENT '上课日期',
  `start_time`     datetime NOT NULL COMMENT '开始时间',
  `end_time`       datetime NOT NULL COMMENT '结束时间',
  `max_persons`    int NOT NULL COMMENT '最大人数',
  `min_persons`    int NOT NULL DEFAULT 2 COMMENT '最低开课人数',
  `booked_persons` int NOT NULL DEFAULT 0 COMMENT '已预约人数',
  `status`         tinyint NOT NULL DEFAULT 1 COMMENT '状态：1待上架 2已上架 3已取消 4已结束',
  `create_by`      bigint unsigned DEFAULT NULL COMMENT '创建人ID',
  `create_time`    datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by`      bigint unsigned DEFAULT NULL COMMENT '更新人ID',
  `update_time`    datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='排课信息表';
```

## 2.3 数据模型

### 2.3.1 `ScheduleListItemVO` / `ScheduleDetailVO`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 排课ID |
| `storeId` / `storeName` | string | 门店 |
| `courseId` / `courseName` | string | 课程 |

| `classroomId` / `classroomName` | string | 教室 |
| `startTime` / `endTime` | string | `yyyy-MM-dd HH:mm:ss` |
| `scheduleDate` | string | **上课日期** `yyyy-MM-dd`（筛选与日期条都用它） |
| `maxPersons` / `minPersons` | integer | 最大人数／最低开课人数 |
| `bookedPersons` | integer | 已预约人数（一期恒 0） |
| `status` | integer | 落库状态码 `1`/`2`/`3`/`4` |
| `statusText` | string | 展示文案：待上架／已上架／已取消／已结束 |

两个 VO 字段相同（列表已经带了排课全部业务字段，不再裁剪）。

### 2.3.2 `ScheduleCreateDTO` / `ScheduleUpdateDTO`

两个请求模型字段相同：`storeId`、`courseId`、`coachId`、`classroomId`、`startTime`、`endTime`、`maxPersons`、`minPersons`。**不含** `status`、`bookedPersons`、**`courseType`** 与 **`scheduleDate`**（课种快照由服务端从课程取、上课日期由服务端从开始时间推导）。使用 `@Valid` 校验非空；业务范围校验在 service。

### 2.3.3 `ScheduleQuery`

列表筛选与分页：`storeId`、`courseId`、`courseType`、`coachId`、`startDate`、`endDate`、`status`、`pageNum`、`pageSize`（上限 100）。

### 2.3.4 状态接口的入参

只有一个字段，直接用查询参数 `status`，**不建 DTO**。

## 3.2 类与职责

| 类 | 职责 |
|---|---|
| `ScheduleController` | 管理端请求、校验、装配响应；**不写业务规则** |
| `SchedulePublicController` | 用户端免登录查询（`@Anonymous`），只读 |
| `ScheduleService` / `ScheduleServiceImpl` | 关联对象与教室归属校验、时间与人数校验、14 天窗口、重复排课与教练时间冲突校验、编辑与状态流转校验、排课 CRUD；对外提供用户端查询方法 |
| `ScheduleDao` / `ScheduleDaoImpl` | 组装筛选、分页、稳定排序；区间相交查询与完全同时段查询 |
| `ScheduleMapper` | 继承 `BaseMapper<ScheduleDO>` |
| `ScheduleDO` | 与 `t_schedule` 对应 |
| `ScheduleCreateDTO` / `ScheduleUpdateDTO` | 新增／修改入参（不含 `status`、`bookedPersons`） |

| `ScheduleListItemVO` / `ScheduleDetailVO` | 接口出参 |
| `ScheduleStatusEnum` | 按落库 `status` 返回状态文案；管理端：待上架／已上架／已取消／已结束，用户端：可约／已取消／已结束 |
| `ScheduleConverter` | DTO、DO、VO 转换（含跨模块名称补齐后的装配） |

# 4、运行流程

## 4.1 查询列表
1. Controller 校验 `ScheduleQuery`（`pageSize` 上限 100、`status` ∈ {1,2,3,4}；按存储状态筛选）。
2. Service 调 DAO 分页查询（**日期区间直接筛 `schedule_date`**），按 `update_time DESC, id DESC` 排序（管理端列表；用户端排序见用户端接口详细设计）。
3. Service 批量调 `StoreService` / `CourseService` / `CoachService` / `ClassroomService` 补齐名称（**按 ID 去重后批量查，避免 N+1**）。
4. Service 按 `status` 通过 `ScheduleStatusEnum` 翻译 `statusText`，转 VO 返回。

## 4.2 查询详情
1. Service 按 ID 查询；不存在 → `404`。
2. 补齐四个对象的名称，关联资料已删除时名称为空字符串；按 `status` 翻译状态文案并返回。

## 4.3 新增排课

1. Controller 校验必填、ID 与时间格式。
2. Service 调 `StoreService`、`CourseService`、`CoachService`、`ClassroomService` 校验关联对象存在；不存在返回 `404`。
3. 校验教室归属所选门店，`startTime < endTime` 且同一自然日，`maxPersons > 0`、`1 <= minPersons <= maxPersons`，上课日期处于今天起 14 天内（含今天）。
4. **重复排课检查**：查询同一门店、同一课程、完全相同起止时间且 `status <> 3` 的排课；查到返回 `409`：“该门店该课程在此时间已有排课”。
5. **教练时间冲突检查**：查询同一教练、`status <> 3` 且满足 `已有 start_time < 新 endTime AND 已有 end_time > 新 startTime` 的排课；查到返回 `409`：“该教练在此时间段已有排课”。上一节结束时间等于下一节开始时间允许相接。
6. 校验通过后，从课程复制 `course_type`，由开始时间推导 `schedule_date`，插入 `status = 1`、`booked_persons = 0`；主键与审计字段由公共机制处理。
7. 返回统一成功响应，不返回新 ID。

## 4.4 修改排课

1. Controller 校验排课 ID、必填字段与时间格式。
2. Service 按 ID 查询排课；不存在返回 `404`，非待上架返回 `409`。
3. 执行新增流程第 2～5 步的校验；重复排课与教练时间冲突查询增加 `id <> 当前 scheduleId`，排除自身。
4. 更新资料字段；更换课程时刷新课种快照，开始时间变化时刷新 `schedule_date`，保留 `status`、`booked_persons`。
5. 返回最新 `ScheduleDetailVO`。

## 4.5 状态流转
1. Service 按 ID 查询排课；不存在返回 `404`。
2. `status ∈ {3,4}` → `409`（终态）。
3. 目标 = 当前 → **直接按成功返回**（幂等）。
4. 校验合法流转（`1→2`、`2→1`、`2→3`）；非法 → `409`。
5. 只更新 `status` 列；返回统一成功响应。

## 4.6 删除排课

1. Service 按 ID 查询排课；不存在返回 `404`。
2. 按 ID 删除排课记录，返回统一成功响应。

## 4.7 结束状态定时维护（后续交付）

1. 后续增加定时任务，以当前时间作为本轮截止时间，分批扫描 `status = 2 AND end_time < 本轮截止时间` 的排课。
2. 按排课 ID 且 `status = 2 AND end_time < 本轮截止时间` 条件更新 `status = 4`；已取消、已结束及已删除的记录不更新。任务只更新排课记录。
3. 更新失败的记录留待下一轮扫描，重复扫描不改变已结束的记录。
4. 任务频率和每批数量在交付时确定。查询与展示只读取 `status`；已结束状态以任务更新为准，查询接口不按时间推导或写入状态。

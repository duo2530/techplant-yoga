## 1.3 数据库物理模型

### 1.3.1 建表语句

```sql
CREATE TABLE `t_reservation` (
  `id` bigint unsigned NOT NULL COMMENT '预约ID',
  `request_id` varchar(36) NOT NULL COMMENT '请求幂等标识',
  `member_id` bigint unsigned NOT NULL COMMENT '会员ID',
  `schedule_id` bigint unsigned NOT NULL COMMENT '排课ID',
  `start_time` datetime NOT NULL COMMENT '开始时间',
  `end_time` datetime NOT NULL COMMENT '结束时间',
  `persons` int NOT NULL COMMENT '预约人数',
  `member_card_id` bigint unsigned NOT NULL COMMENT '会员卡ID',
  `status` tinyint NOT NULL DEFAULT 1 COMMENT '状态：1已预约 2已取消 3已签到',
  `reservation_time` datetime NOT NULL COMMENT '预约时间',
  `cancel_time` datetime DEFAULT NULL COMMENT '取消时间',
  `cancel_reason` tinyint DEFAULT NULL COMMENT '取消原因：1会员主动取消 2排课取消',
  `check_in_time` datetime DEFAULT NULL COMMENT '签到时间',
  `create_by` bigint unsigned DEFAULT NULL COMMENT '创建人ID',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by` bigint unsigned DEFAULT NULL COMMENT '更新人ID',
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_member_request` (`member_id`, `request_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='课程预约单';

CREATE TABLE `t_member_card_transaction` (
  `id` bigint unsigned NOT NULL COMMENT '流水ID',
  `member_card_id` bigint unsigned NOT NULL COMMENT '会员卡ID',
  `member_id` bigint unsigned NOT NULL COMMENT '会员ID',
  `reservation_id` bigint unsigned NOT NULL COMMENT '预约ID',
  `change_type` tinyint NOT NULL COMMENT '类型：1预约扣次 2取消返次',
  `persons` int NOT NULL COMMENT '预约人数',
  `change_times` int NOT NULL COMMENT '变动次数',
  `before_times` int NOT NULL COMMENT '变动前次数',
  `after_times` int NOT NULL COMMENT '变动后次数',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '变动时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_reservation_type` (`reservation_id`, `change_type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='会员卡次数流水';
```

`uk_member_request` 保证提交重试幂等；不能对 `(member_id, schedule_id)` 直接设置全量唯一约束，因为取消后允许重新预约。未取消预约唯一性通过会员行锁串行校验。`uk_reservation_type` 保证同一预约的扣次、返次流水分别至多一笔。

Controller 负责鉴权上下文、参数校验和响应包装，不实现扣次规则。ReservationService 编排事务、状态校验、快照和占位；MemberCardService 提供锁卡、资格校验与条件扣返次；MemberCardTransactionService 在同一事务追加流水。DAO 负责筛选、分页、锁行和条件更新；Converter 负责关联资料、上课时间快照和状态文案装配。

跨模块通过 Service 协作，事务使用同一个数据源和事务管理器，内层加入外层事务，不使用独立提交或异步扣返次。

## 3.2 事务与并发

1. 预约创建依次锁排课、会员、会员卡；取消依次锁排课、预约、会员卡；签到依次锁排课、预约。加锁后重新校验时间与状态；同会员创建预约由会员行锁串行化，重复预约及幂等键复查使用当前读（`SELECT ... FOR UPDATE`）。同会员允许预约时间重叠的不同排课。会员锁当前保留，用于会员存在性当前读和同会员请求串行化，其简化应单独验证。
2. 名额增减、扣返次及流水与预约写入同一事务；人数和余额通过条件更新保证不超额、不为负。requestId 与流水唯一键保证重试不重复处理，失败整体回滚。

# 4、运行流程

用户端预约课程、取消预约、预约签到、我的预约列表四个接口的运行流程分别维护在[用户端接口详细设计](用户端接口详细设计.md)中，本节描述管理端预约列表查询接口。

## 4.1 查询预约列表

`GET /admin/reservations`

1. 管理端鉴权链校验管理员登录态，失败返回 401。
2. Controller 校验关联 ID、状态、卡类型、日期范围及分页参数；非法参数或起始日期晚于结束日期返回参数错误。
3. Service 将筛选条件传给 DAO；storeId、courseId 通过排课关联筛选，scheduleId、memberId 与预约状态按对应字段筛选，上课日期范围按预约 start_time 快照转换为时间区间。
4. DAO 按相同筛选条件统计总数并按 reservation_time DESC、id DESC 分页；按排课查询名单仍使用该接口，不以本页记录数代替整节课预约人数。
5. 批量读取本页排课、会员、会员卡及课程、教练、门店、教室资料，装配当前名称、会员姓名和手机号；基础展示资料缺失时对应字段返回 null。
6. 由预约时间快照计算上课日期、时长，分别翻译预约状态与排课状态；转换 ReservationAdminItemVO，不输出用户端操作按钮。
7. 返回 TableDataInfo；无符合记录或页码超界时返回空 rows，total 为筛选结果总数。查询不修改状态、人数、余额或流水。

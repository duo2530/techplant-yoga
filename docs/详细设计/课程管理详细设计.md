## 1.3 数据库物理模型

### 1.3.1 建表语句

```sql
CREATE TABLE `t_course` (
  `id`          bigint unsigned NOT NULL COMMENT '课程ID',
  `name`        varchar(64)   NOT NULL COMMENT '课程名称（全平台唯一）',
  `course_type` tinyint       NOT NULL COMMENT '课种：1团课 2精品课 3私教课 4特色课',
  `cover_url`   varchar(255)  DEFAULT NULL COMMENT '课程封面URL（单图）',
  `intro`       varchar(1024) DEFAULT NULL COMMENT '课程介绍',
  `difficulty`  tinyint       NOT NULL COMMENT '课程难度：1~5星',
  `create_by`   bigint unsigned DEFAULT NULL COMMENT '创建人ID',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by`   bigint unsigned DEFAULT NULL COMMENT '更新人ID',
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_course_name` (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='课程基础信息表';
```

### 2.2.1 查询课程列表

`GET /admin/courses`

列表按 `update_time DESC, id DESC` 排序。

#### 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|

| `name` | query | string | 否 | 课程名称，模糊匹配，最长 64 |
| `courseType` | query | integer | 否 | 1～4，不传不限 |
| `pageNum` | query | integer | 否 | 默认 1，最小 1 |
| `pageSize` | query | integer | 否 | 默认 10，最大 100 |

> 返回示例

> 200 Response

```json
{
  "total": 1,
  "rows": [

      "id": "1856739201475238001",
      "name": "哈他瑜伽",

```

#### 返回结果

| 状态码 | 状态码含义 | 说明 | 数据模型 |
|:---|---|---|---|
| 200 | 成功 | 分页返回课程列表 | `TableDataInfo<CourseListItemVO>` |

| 500 | 参数校验失败 | `courseType` 不在 1~4；`pageSize` 超过上限 | `AjaxResult<Void>` |

# 4、运行流程

## 4.1 查询列表
1. Controller 校验 `CourseQuery`（`pageSize` 上限 100、`courseType` 取值范围）。
2. Service 调 DAO 分页查询（只 select `id/name/course_type/cover_url/difficulty/审计时间`），按 `update_time DESC, id DESC` 排序。
3. 转 `CourseListItemVO` 返回。

## 4.2 查询详情
1. Service 按 ID 查询；不存在 → `404`。
2. 转 `CourseDetailVO`（含 `intro`）返回。

## 4.3 新增课程
1. Controller 校验必填、长度与取值范围（`courseType` ∈ 1~4；`difficulty` ∈ 1~5）。
2. Service 按 `name` 查重；重复 → `409`。
3. 转 DO 插入；主键与审计字段由公共机制处理。

## 4.4 修改课程
1. Service 按 ID 查询；不存在 → `404`。
2. 按 `name` 查重（**排除自身**）；重复 → `409`。
3. 全量覆盖业务字段并更新；返回最新详情。

## 4.5 删除课程

1. Service 开启数据库事务，按主键 `SELECT ... FOR UPDATE` 锁定本课程行并当前读；不存在返回 `404`。这与排课写入时调用 `CourseService.lockByIdsForUpdate` 获取的是同一行锁，不先做无锁引用检查。
2. 锁内调用 `ScheduleService.countActiveByCourseId`，以当前读取得 `end_time > 当前时间 AND status IN (1,2)` 的引用记录并统计；大于 0 返回 `409`，提示“该课程仍有 N 节未结束的排课，无法删除”。已取消或已结束的历史排课不阻塞，历史关联信息按用户端约定空值兜底。
3. 引用统计失败直接终止并回滚，不降级放行。统计与删除必须处于同一数据库事务，同一行锁一直保持到提交／回滚。
4. 无阻塞引用才物理删除并提交。并发排课写请求随后取得课程锁时应发现对象不存在，返回 `404`；已持锁的排课请求若先提交，删除请求取得锁后会看到新引用并被拒绝。死锁或锁等待失败先回滚，再有限重试完整事务，不重试业务门禁失败。

## 4.6 对外加锁契约

`CourseService.lockByIdsForUpdate(ids)` 在调用方已开启的数据库事务内参与执行（不得使用 `REQUIRES_NEW`）。对 ID 去重、升序后逐行按主键 `SELECT id ... FOR UPDATE`，对象缺失抛 `404`；不返回持久化实体，不在方法返回时提前释放锁。排课写入、课程删除锁同一实际数据行；公共顺序为“门店 → 教练 → 课程 → 教室 → 排课”，各类内部按 ID 升序。历史结束任务允许跳过已删除主数据，使用单独的“仅锁现存行”入口，不改变新增／修改排课的存在性要求。

## 1.3 数据库物理模型

### 1.3.1 建表语句

```sql
CREATE TABLE `t_coach` (
  `id`          bigint unsigned NOT NULL COMMENT '教练ID',
  `name`        varchar(32)  NOT NULL COMMENT '姓名',
  `avatar_url`  varchar(255) DEFAULT NULL COMMENT '头像URL',
  `intro`       varchar(512) DEFAULT NULL COMMENT '简介',
  `phone`       varchar(32)  DEFAULT NULL COMMENT '联系电话（管理端专用）',
  `gallery`     json DEFAULT NULL COMMENT '相册：JSON数组，最多5个URL',
  `level`     tinyint DEFAULT 1 COMMENT '教练等级：1-普通教练；2-金牌教练',
  `create_by`   bigint unsigned DEFAULT NULL COMMENT '创建人ID',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by`   bigint unsigned DEFAULT NULL COMMENT '更新人ID',
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  KEY `idx_coach_name` (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='教练信息表';
```

`GET /admin/coaches`

| `name` | query | string | 否 | 教练姓名，模糊匹配，最长 32 |
| `pageNum` | query | integer | 否 | 默认 1，最小 1 |
| `pageSize` | query | integer | 否 | 默认 10，最大 100 |

> 返回示例

> 200 Response

# 4、运行流程

## 4.1 查询列表
1. Controller 校验 `CoachQuery`（`pageSize` 上限 100）。
2. Service 调 DAO 分页查询（只 select `id/name/avatar_url/phone/审计时间`），按 `update_time DESC, id DESC` 排序。
3. 转 `CoachListItemVO` 返回。

## 4.2 查询详情
1. Service 按 ID 查询；不存在 → `404`。
2. 反序列化 `gallery` 为 `List<String>`，转 `CoachDetailVO` 返回。

## 4.3 新增教练
1. Controller 校验 `name` 非空、长度与各字段长度。
2. Service 校验 `gallery` 元素数 ≤ 5；超过 → `409`。
3. 序列化 `gallery` 为 JSON 字符串，插入；主键与审计字段由公共机制处理。

## 4.4 修改教练
1. Service 按 ID 查询；不存在 → `404`。
2. 校验 `gallery` 元素数 ≤ 5；超过 → `409`。
3. 全量覆盖业务字段并更新；返回最新详情。

## 4.5 删除教练

1. Service 开启数据库事务，按主键 `SELECT ... FOR UPDATE` 锁定本教练行并当前读；不存在返回 `404`。这与排课写入时调用 `CoachService.lockByIdsForUpdate` 获取的是同一行锁，不先做无锁引用检查。
2. 锁内调用 `ScheduleService.countActiveByCoachId`，以当前读取得 `end_time > 当前时间 AND status IN (1,2)` 的引用记录并统计；大于 0 返回 `409`，提示“该教练仍有 N 节未结束的排课，无法删除”。已取消或已结束的历史排课不阻塞，历史关联信息按用户端约定空值兜底。
3. 引用统计失败直接终止并回滚，不降级放行。统计与删除必须处于同一数据库事务，同一行锁一直保持到提交／回滚。
4. 无阻塞引用才物理删除并提交。并发排课写请求随后取得教练锁时应发现对象不存在，返回 `404`；已持锁的排课请求若先提交，删除请求取得锁后会看到新引用并被拒绝。死锁或锁等待失败先回滚，再有限重试完整事务，不重试业务门禁失败。

## 4.6 对外加锁契约

`CoachService.lockByIdsForUpdate(ids)` 在调用方已开启的数据库事务内参与执行（不得使用 `REQUIRES_NEW`）。对 ID 去重、升序后逐行按主键 `SELECT id ... FOR UPDATE`，对象缺失抛 `404`；不返回持久化实体，不在方法返回时提前释放锁。排课写入、教练删除锁同一实际数据行；公共顺序为“门店 → 教练 → 课程 → 教室 → 排课”，各类内部按 ID 升序。历史结束任务允许跳过已删除主数据，使用单独的“仅锁现存行”入口，不改变新增／修改排课的存在性要求。

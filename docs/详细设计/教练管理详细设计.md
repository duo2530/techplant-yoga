## 1.2 数据库逻辑模型

### 1.2.1 `t_coach` 字段定义

| 字段 | 中文名 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---:|:---:|---:|---|
| `id` | 教练ID | bigint unsigned | 是 | — |  |
| `name` | 姓名 | varchar(32) | 是 | — |                                  |
| `avatar_url` | 头像 | varchar(255) | 否 | NULL | 图片 URL |
| `intro` | 简介 | varchar(512) | 否 | NULL | 纯文本 |
| `phone` | 联系电话 | varchar(32) | 否 | NULL | 管理端专用 |
| `gallery` | 相册 | json | 否 | NULL | **JSON 数组**，最多 5 个图片 URL |
| `level` | 教练等级 | tinyint | 是 | 1 | 教练等级：1-普通教练；2-金牌教练 |
| `create_by` | 创建人 | bigint unsigned | 否 | NULL | 公共审计填充 |
| `create_time` | 创建时间 | datetime | 是 | CURRENT_TIMESTAMP | 公共审计填充 |
| `update_by` | 更新人 | bigint unsigned | 否 | NULL | 公共审计填充 |
| `update_time` | 更新时间 | datetime | 是 | CURRENT_TIMESTAMP | ON UPDATE |

教练为**平台级**主数据，不归属门店、不与门店建立关联；排课直接引用教练 ID，不通过门店取教练。`level` 表示教练等级，由独立的等级接口维护，资料新增与编辑不改变等级。

### 1.2.2 枚举值


| 枚举 | 值 | 文案 |
|---|--:|---|
| `level` | 1 | 普通教练 |
| `level` | 2 | 金牌教练 |

新库与存量数据升级后，所有教练默认为普通教练；金牌仅由管理员通过等级接口设置，不做样例数据回填。

## 1.3 数据库物理模型

### 1.3.1 建表语句

```sql
CREATE TABLE `t_coach` (
  `id`          bigint unsigned NOT NULL COMMENT '教练ID',
  `name`        varchar(32)  NOT NULL COMMENT '姓名',
  `avatar_url`  varchar(255) DEFAULT NULL COMMENT '头像URL',
  `intro`       varchar(512) DEFAULT NULL COMMENT '简介',
  `phone`       varchar(32)  DEFAULT NULL COMMENT '联系电话（管理端专用）',
  `gallery`     json DEFAULT NULL COMMENT '相册：JSON数组，最多5个URL',
  `level`       tinyint      NOT NULL DEFAULT 1 COMMENT '教练等级：1普通 2金牌',
  `create_by`   bigint unsigned DEFAULT NULL COMMENT '创建人ID',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by`   bigint unsigned DEFAULT NULL COMMENT '更新人ID',
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  KEY `idx_coach_name` (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='教练信息表';
```

| `pageSize` | query | integer | 否 | 每页条数，1～100，未传时默认 10 |

### 2.2.5 删除教练

`DELETE /admin/coaches/{coachId}`

按 ID 物理删除，无请求体。删除前统计该教练名下未结束且状态为待上架／已上架的排课，存在引用时拒绝删除；统计失败同样拒绝，不降级放行。

#### 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `Authorization` | header | string | 是 | Bearer <管理端 token>，不能使用会员 token |
| `coachId` | path | string | 是 | 教练 ID |

> 返回示例

> 200 Response

```json
{
  "code": 200,
  "msg": "操作成功"
}
```

#### 返回结果

| 状态码 | 状态码含义 | 说明 | 数据模型 |
|:---|---|---|---|
| 200 | 成功 | 删除成功 | `AjaxResult<Void>` |
| 400 | 参数格式非法 | `coachId` 不能转换为整数 | `AjaxResult<Void>` |
| 401 | 登录失效 | 管理端未登录或 token 无效 | `AjaxResult<Void>` |
| 404 | 教练不存在 | 教练不存在或已被删除 | `AjaxResult<Void>` |
| 409 | 删除门禁 | 教练仍有未结束且状态为待上架／已上架的排课；或引用检查未完成（fail-closed） | `AjaxResult<Void>` |


### 2.2.6 设置／取消金牌教练

`PUT /admin/coaches/{coachId}/level`

设置或取消金牌教练，无请求体。由 `CoachController.updateLevel` 承载，与教练资料接口归属同一个 Controller，只要求管理端登录；重复设置同一等级按成功处理。Swagger 按 Java 签名呈现：`coachId` 为路径参数，`level` 为**必填 query 整数**参数。

#### 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `Authorization` | header | string | 是 | Bearer <管理端 token>，不能使用会员 token |
| `coachId` | path | string | 是 | 教练 ID，字符串形式的雪花 ID（Swagger 按 `Long` 呈现为整型路径参数） |
| `level` | query | integer | 是 | 目标等级：1 普通教练（取消金牌）；2 金牌教练 |

> 返回示例

> 200 Response

```json
{
  "code": 200,
  "msg": "操作成功"
}
```

#### 返回结果

| 状态码 | 状态码含义 | 说明 | 数据模型 |
|:---|---|---|---|
| 200 | 成功 | 等级设置成功；目标等级与当前等级相同时同样成功 | `AjaxResult<Void>` |
| 400 | 参数校验失败 | `coachId` 格式非法（提示「参数[coachId]格式非法」）；`level` 缺失（提示「参数[level]不能为空」）、非数字（提示「参数[level]格式非法」）或不在 1／2 中（提示「教练等级取值为 1 或 2」） | `AjaxResult<Void>` |
| 401 | 登录失效 | 管理端未登录或 token 无效 | `AjaxResult<Void>` |
| 404 | 教练不存在 | 教练不存在或已被删除 | `AjaxResult<Void>` |

> 上表为统一响应体中的业务码，与 HTTP 状态码分离。参数异常由 `GlobalExceptionHandler` 统一处理，教练管理接口的参数绑定与校验错误统一返回业务码 `400`。

## 2.4 登录与菜单配置

教练等级维护与新增、修改、删除一致，只要求管理端登录，不配置额外的方法级权限或按钮权限。游客和会员 token 调用管理端接口返回业务码 401。

管理端继续使用「教练管理」菜单（`sys_menu` 2003）；「设为金牌／取消金牌」按钮按当前等级显示。已有库执行 `backend/sql/yoga_upgrade_v2.6_gold_coach.sql`，补充等级列并清理已废止的等级按钮及其角色绑定，其它菜单与角色授权保持不变；新建库不创建独立等级按钮。

`level` 为必填参数，缺失或格式错误时由 `GlobalExceptionHandler` 在进入等级方法前返回 400。

## 2.5 管理端操作说明

1. 进入【经营基础 → 教练管理】，列表新增「等级」列，按 `level` 显示「金牌」（金牌教练）或「普通」（普通教练）标签。
2. 操作列依次为「修改」、「设为金牌／取消金牌」、「删除」；按当前等级只显示「设为金牌」（普通教练）或「取消金牌」（金牌教练）。
3. 点击后弹出二次确认（如「是否确认将教练"林教练"设为金牌？」），确认后调用 `PUT /admin/coaches/{coachId}/level?level=2`（设为金牌）或 `?level=1`（取消金牌）；成功提示「设为金牌成功／取消金牌成功」并刷新当前列表，失败由请求拦截器提示，列表保持原状态。
4. 新增教练固定为普通教练；资料新增／编辑弹窗不含等级字段，编辑资料后等级保持不变。
5. 等级变更立即影响用户端首页「金牌教练」栏目：用户端在首页再次显示时重新拉取金牌列表；取消金牌不会使已打开的教练资料链接失效。

前端接口统一维护在 `frontend/pc/src/api/coach/coach.js`，等级操作使用 `updateCoachLevel(coachId, level)`，通过查询参数传递等级；页面继续使用 `src/views/coach/index.vue`。

## 2.6 升级与回滚说明

1. **升级**：已有库执行 `backend/sql/yoga_upgrade_v2.6_gold_coach.sql`，缺失时增加 `level` 列，并清理已废止的等级按钮及角色绑定；新建库导入最新 `yoga.sql`。列已存在时不重置等级，清理权限配置不影响教练资料、排课及其它菜单授权，脚本可重复执行。
2. **回滚顺序**：先回退用户端，再回退管理端，最后回退后端。保留 `level` 列与等级数据时旧后端可直接继续运行：资料更新使用显式更新列、不含 `level`，不会改写等级。
3. **撤销列不属于自动回滚**：需要撤销 `level` 列时另行备份并按数据库维护流程执行，不随发布回滚自动 `DROP`，避免丢失金牌配置。等级操作不依赖独立按钮权限，无需恢复等级按钮与角色绑定。

# 4、运行流程

## 4.1 查询列表
1. Controller 校验 `CoachQuery`（`pageSize` 上限 100）。
2. Service 调 DAO 分页查询（只 select `id/name/avatar_url/phone/level/审计时间`），按 `id DESC` 排序。
3. 转 `CoachListItemVO`，直接返回 `level` 数值。

## 4.2 查询详情
1. Service 按 ID 查询；不存在 → `404`。
2. 反序列化 `gallery` 为 `List<String>`，转 `CoachDetailVO` 返回（含 `level`）。

## 4.3 新增教练
1. Controller 校验 `name` 非空、长度与各字段长度。
2. Service 校验 `gallery` 元素数 ≤ 5；超过 → `409`。
3. 序列化 `gallery` 为 JSON 字符串，显式写入 `level = 1` 后插入；主键与审计字段由公共机制处理。请求中的等级字段不参与新增。

## 4.4 修改教练
1. Service 按 ID 查询；不存在 → `404`。
2. 校验 `gallery` 元素数 ≤ 5；超过 → `409`。
3. 仅全量覆盖 `name`、`avatar_url`、`intro`、`phone`、`gallery`，不更新 `level`；返回最新详情，包含原等级及文案。

## 4.5 删除教练

1. Service 按 ID 查询教练；不存在返回 `404`。
2. 调排课模块统计该教练名下未结束且状态为待上架／已上架的排课；有引用返回 `409` 并给出数量，统计异常同样返回 `409`（fail-closed）。
3. 按 ID 物理删除教练记录，返回统一成功响应。



## 4.6 设置／取消金牌教练

1. 请求先经管理端安全链校验登录态：未登录、会员 token 或其他无效凭证返回 `401`。
2. 参数绑定：`coachId` 为路径 `Long`、`level` 为必填 query `Integer`；缺失或格式错误由 `GlobalExceptionHandler` 的 `@ExceptionHandler` 在进入方法前返回 `400`——`level` 缺失「参数[level]不能为空」、非数字「参数[level]格式非法」、`coachId` 非法「参数[coachId]格式非法」。
3. 管理员登录后可维护等级，无需额外按钮授权。
4. `CoachService.updateLevel` 校验目标等级只能是 1 或 2，其他数值返回 `400`「教练等级取值为 1 或 2」；调 DAO 按 ID 查询教练，不存在返回 `404`。
5. 当前等级与目标相同时返回成功；否则通过 DAO 的独立等级更新列更新 `level` 与更新人、更新时间，不写回资料字段。
6. 返回统一成功响应。

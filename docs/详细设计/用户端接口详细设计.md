# 瑜伽普拉提用户端接口详细设计文档

**当前设计范围：会员登录、排课浏览、我的会员卡查询，以及预约课程、取消预约、预约签到与我的预约查询。** 账户与会员共用 `t_member`；预约数据、扣次流水和跨模块事务见[预约管理详细设计](预约管理详细设计.md)。本文描述接口契约，不代表对应功能已经实现。


## 1、数据架构

“我的会员卡”复用 `t_member_card`，通过 `member_id` 关联登录会员，不新增业务表。字段、卡号、发卡、开卡与停卡规则统一见[会员卡管理详细设计](会员卡管理详细设计.md)。卡片展示状态根据开卡时间、停卡时间、有效期与剩余次数实时计算，不新增数据库状态字段。

预约使用 `t_reservation`，次数变动使用 `t_member_card_transaction`。一次预约对应一个会员、一节排课、一张会员卡和一组预约人数；预约成功扣次并占位，取消预约返次并释放名额，签到不重复扣次。时间统一使用 `Asia/Shanghai`。预约状态与排课状态分别维护。

### 2.2.1 查询门店列表

`GET /api/stores`

列表按 `region_code ASC, name ASC, id DESC` 排序。按区域及门店名称／地址关键字筛选；只返回现存门店，当前门店由小程序本地保存。

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `regionCode` | query | string | 否 | 所在区域 code，精确匹配；取值须在 store_region 字典中 |
| `keyword` | query | string | 否 | 门店名称／地址关键字，模糊匹配，最长 64 |
| `pageNum` | query | integer | 是 | 页码，最小 1 |
| `pageSize` | query | integer | 是 | 每页条数，1～100 |

### 2.2.4 发送短信验证码

`POST /api/auth/sms-code`

免登录。发送间隔 60 秒、有效期 5 分钟。验证码错误允许多次重试，有效期内不限制校验次数。发送新码作废旧码，响应不返回验证码。

#### 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `phone` | body | string | 是 | 手机号，最长 32，校验手机号格式 |
| `scene` | body | string | 是 | register 注册／reset 忘记密码 |

> 请求示例

```json
{
  "phone": "13800138000",
  "scene": "register"
}
```

> 返回示例

> 200 Response

```json
{
  "code": 200,
  "msg": "验证码已发送"
}
```

#### 返回结果

| 状态码 | 状态码含义 | 说明 | 数据模型 |
|:---|---|---|---|
| 200 | 成功 | 发送短信验证码成功 | `AjaxResult<Void>` |
| 404 | 手机号未注册 | reset 场景仅允许已注册手机号 | `AjaxResult<Void>` |
| 409 | 状态冲突 | 发送过频，或 register 场景手机号已注册 | `AjaxResult<Void>` |
| 500 | 参数校验失败 | phone 或 scene 缺失或取值非法 | `AjaxResult<Void>` |

### 2.2.5 注册

`POST /api/auth/register`

免登录。有未注册会员档案时补齐同一行登录信息，保留会员 ID 和资料；无档案则新建 V0 会员。已注册拒绝重复注册。注册成功不签发 token、不刷新最后登录时间，前端跳回登录页。

#### 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `phone` | body | string | 是 | 手机号，最长 32，校验手机号格式 |
| `smsCode` | body | string | 是 | 6 位数字验证码 |
| `password` | body | string | 是 | 8～20 位，至少包含字母与数字 |

> 返回示例

> 200 Response

```json
{
  "code": 200,
  "msg": "注册成功，请登录"
}
```

#### 返回结果

| 状态码 | 状态码含义 | 说明 | 数据模型 |
|:---|---|---|---|
| 200 | 成功 | 注册成功，不返回登录态 | `AjaxResult<Void>` |
| 409 | 注册冲突 | 手机号已注册、验证码错误／过期或并发注册冲突 | `AjaxResult<Void>` |
| 500 | 参数校验失败 | 必填字段缺失、手机号或密码格式非法 | `AjaxResult<Void>` |

### 2.2.6 登录

`POST /api/auth/login`

免登录。手机号不存在、未注册或密码错误统一提示“手机号或密码错误”。成功刷新最后登录时间，签发登录态，有效期 7 天，不自动续期。

#### 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `phone` | body | string | 是 | 手机号，最长 32，校验手机号格式 |
| `password` | body | string | 是 | 登录密码，非空 |

> 返回示例

> 200 Response

```json
{
  "code": 200,
  "msg": "登录成功",
  "data": {
    "token": "<member-token>",
    "expireTime": 1792368000000,
    "memberId": "1856739201475235902",
    "memberName": "忻会员8000"
  }
}
```

#### 返回结果

| 状态码 | 状态码含义 | 说明 | 数据模型 |
|:---|---|---|---|
| 200 | 成功 | 返回会员登录态 | `AjaxResult<LoginVO>` |
| 409 | 登录失败 | 手机号不存在、尚未注册或密码错误，统一提示“手机号或密码错误” | `AjaxResult<Void>` |
| 500 | 参数校验失败 | phone 或 password 缺失或格式非法 | `AjaxResult<Void>` |

### 2.2.7 忘记密码

`POST /api/auth/reset-password`

免登录。仅已注册手机号可重置，经验证码校验后更新 BCrypt 哈希，不需要旧密码；本阶段不批量撤销已有登录态。

#### 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `phone` | body | string | 是 | 已注册手机号，最长 32 |
| `smsCode` | body | string | 是 | 6 位数字验证码 |
| `password` | body | string | 是 | 新密码，8～20 位，至少包含字母与数字 |

> 请求示例

```json
{
  "phone": "13800138000",
  "smsCode": "123456",
  "password": "new12345"
}
```

> 返回示例

> 200 Response

```json
{
  "code": 200,
  "msg": "密码已重置"
}
```

#### 返回结果

| 状态码 | 状态码含义 | 说明 | 数据模型 |
|:---|---|---|---|
| 200 | 成功 | 忘记密码成功 | `AjaxResult<Void>` |
| 404 | 手机号未注册 | 该手机号尚未注册 | `AjaxResult<Void>` |
| 409 | 验证码校验失败 | 验证码错误／过期 | `AjaxResult<Void>` |
| 500 | 参数校验失败 | 必填字段缺失、手机号或密码格式非法 | `AjaxResult<Void>` |

### 2.2.8 退出登录

`POST /api/auth/logout`

撤销当前会员会话。幂等：token 缺失、已失效或已删除时也返回成功；有效的会员 token 用于定位待清理会话。

#### 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `Authorization` | header | string | 否 | Bearer <会员 token>；有效登录时携带，无请求体 |

> 返回示例

> 200 Response

```json
{
  "code": 200,
  "msg": "退出成功"
}
```

#### 返回结果

| 状态码 | 状态码含义 | 说明 | 数据模型 |
|:---|---|---|---|
| 200 | 成功 | 退出登录成功 | `AjaxResult<Void>` |
| 500 | 系统异常 | 会话清理失败，由统一异常处理器返回提示 | `AjaxResult<Void>` |

### 2.2.10 预约课程

`POST /api/reservations`

#### 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `requestId` | body | string | 是 | 客户端生成的 UUID，同一次提交及网络重试保持不变；重新预约生成新值 |
| `scheduleId` | body | string | 是 | 排课 ID，字符串形式雪花 ID |
| `memberCardId` | body | string | 是 | 本人会员卡 ID，字符串形式雪花 ID |
| `persons` | body | integer | 是 | 预约人数，正整数；不得超过剩余名额，次数卡不得超过剩余次数；年卡固定为 1 |

> 返回示例

> 200 Response

```json
{
  "code": 200,
  "msg": "预约成功"
}
```

#### 返回结果

以下状态码均为统一响应体中的业务码。

| 状态码 | 状态码含义 | 说明 | 数据模型 |
|---|---|---|---|
| 200 | 成功 | 预约成功 | `AjaxResult<Void>` |
| 401 | 登录失效 | 与查询我的会员卡相同的会员鉴权规则 | `AjaxResult<Void>` |
| 404 | 对象不存在 | 排课不存在／待上架、会员卡不存在或不属于本人、必要关联资料已删除 | `AjaxResult<Void>` |

# 4、运行流程

## 4.0 公共会员鉴权

公开浏览、发验证码、注册、登录、忘记密码按接口清单放行；退出允许会话清理，会员卡查询与预约相关接口必须登录。需会员身份的请求按以下顺序校验：

1. 验证会员 JWT，取得 `member_tokens:<uuid>` 登录对象，检查存在性与过期时间；不接受管理端 token。
2. 从会话取得 memberId，检查对应会员仍存在且已注册。会员不存在或 password 为空时返回业务码 401，并尽力删除本次请求对应的失效会话；数据库查询失败不降级放行。
3. 校验通过才写入登录上下文。登录态自然到期或当前用户退出后失效，不维护额外撤销标识与批量会话反向索引。
4. 退出接口允许失效会话幂等清理，不阻止退出处理器执行。当前未交付的业务接口不因存在登录态而开放。

## 4.1 查询门店列表

`GET /api/stores`

1. Controller 校验区域、关键字与分页参数。
2. StoreService 调 DAO 按区域与名称／地址筛选，按 `region_code ASC, name ASC, id DESC` 排序。
3. 转换 StorePublicItemVO，返回 TableDataInfo；当前门店只保存在小程序本地。

## 4.2 查询排课列表

`GET /api/schedules`

1. Controller 校验门店、课种、日期与分页参数。
2. Service 校验门店存在，DAO 固定按门店、排课课种快照、上课日期及 status <> 1 筛选，按 update_time DESC、id DESC 分页。
3. 批量读取课程、教练、门店与教室摘要，装配实时资料；课程封面、难度等关联资料缺失时返回 null。
4. 读取实际 bookedPersons，计算 remainingPlaces、bookable 与状态文案，转换 ScheduleCardVO 并返回 TableDataInfo；无记录返回空列表。

## 4.3 查询排课详情

`GET /api/schedules/{scheduleId}`

1. Controller 校验 scheduleId 格式。
2. Service 查询排课，不存在、已删除或处于待上架时统一返回 404。
3. 读取课程、教练、门店与教室摘要，装配课程简介、教练简介、门店地址；未设置或关联资料缺失的可空字段返回 null。
4. 读取实际预约人数，计算剩余名额及 bookable；查询未取消预约，按接口模型约定生成脱敏 bookers。
5. 返回 AjaxResult<SchedulePublicDetailVO>，不复用管理端详情模型，不修改排课或预约状态。

## 4.4 发送短信验证码

`POST /api/auth/sms-code`

1. 校验手机号与场景；按场景检查已注册／未注册条件。
2. 检查 60 秒发送间隔。
3. 按手机号与场景保存 6 位新验证码（5 分钟有效），作废同场景旧码并通过 SmsSender 发送；验证码校验失败不限制校验次数，允许有效期内多次重试。
4. 不回显验证码；开发固定码由配置控制。

## 4.5 注册

`POST /api/auth/register`

1. 校验手机号、注册场景验证码与密码强度；验证码错误返回 409，保留未过期验证码供重试，校验成功后消费验证码。
2. 将明文密码转换为 BCrypt 哈希，调用 `MemberService.registerByPhone`。已注册拒绝；已有未注册档案按会员 ID 且 `password IS NULL` 条件只更新密码哈希，影响行数为 0 返回 409；无档案则创建 V0 会员，具体流程见会员管理详细设计 §4.6。
3. 保留已有会员 ID、资料与业务关联，并发冲突返回 409。
4. 事务成功后返回“注册成功，请登录”，不签发 token、不更新最后登录时间。

## 4.6 登录

`POST /api/auth/login`

1. 按手机号查询 t_member；会员不存在、未注册（password 为空）或 BCrypt 密码校验失败时，统一返回 409：“手机号或密码错误”。
2. 校验通过后刷新 last_login_time。数据库更新成功后签发会员 JWT，并写入 Redis `member_tokens:<uuid>`，保存 MemberLoginUser 与过期时间；有效期 7 天，不自动续期。
3. 返回 LoginVO（token、expireTime、memberId、memberName）。Redis 会话写入失败不返回成功 token，按统一异常处理；不维护批量会话反向索引。

## 4.7 忘记密码

`POST /api/auth/reset-password`

1. Controller 校验手机号、验证码与新密码格式。
2. Service 检查手机号已注册，校验重置密码场景验证码；错误或过期返回 409，保留未过期验证码供重试，校验成功后消费验证码。
3. 将新密码转换为 BCrypt 哈希并更新会员密码，保留“不批量撤销旧会话”的契约。
4. 返回统一成功响应，不签发新登录态。

## 4.8 退出登录

`POST /api/auth/logout`

1. 退出请求允许进入会话清理处理器，token 缺失或失效时不被登录校验阻断。
2. 有效会员 token 解析出当前会话标识，删除对应 Redis 会话，不影响该会员其他会话。
3. token 缺失、过期或会话已删除时仍返回幂等成功；会话清理异常由统一异常处理器返回。

## 4.9 查询我的会员卡

`GET /api/member-cards`

1. 会员鉴权链按 §4.0 校验登录态与会员存在性，失败返回 401；本接口不配置匿名放行。
2. Controller 校验分页参数，调用 `MemberContextUtils.requireMemberId()` 获取会员 ID，将其作为独立参数传给 `MemberCardService.pageForMember`。
3. DAO 以 `member_id = 当前会员 ID` 为固定条件分页查询，按 `id DESC` 排序并统计本人会员卡总数；不增加当前门店或可用状态条件。无卡直接返回空 rows 与 total = 0。
4. 批量读取当前页次数卡适用门店信息；年卡不将开卡门店作为适用门店。门店已删除时保留卡记录与门店 ID，生成缺失门店文案。
5. 统一取本次请求的上海时区当前时间，按 §2.2.9 计算展示状态、总次数与年卡剩余天数，转换为 `MemberCardPublicItemVO`。不修改会员卡、有效期、剩余次数或流水。
6. Controller 将分页结果包装为 TableDataInfo。前端按卡片分类展示对应样式，根据空值展示未开卡提示，并依据 total 控制翻页与底部文案。

## 4.10 预约课程

`POST /api/reservations`

1. 按公共会员鉴权取得当前 memberId，Controller 校验 requestId、scheduleId、memberCardId 与 persons，不接受客户端指定会员身份。
2. Service 按 memberId + requestId 查询原预约；存在则比较排课、会员卡和人数，参数一致则直接返回成功，不重复创建预约、占位或扣次；参数不同返回 409。
3. 开启事务，按预约模块锁顺序读取排课、会员和会员卡，并复查幂等键。取得锁后取上海当前时间，校验排课已上架、未开始、14 天窗口、剩余名额与必要关联资料。
4. 校验卡属于本人、已开卡、未停卡，当前及课程时间均在有效期内，门店和课种适用；校验人数与同排课重复预约。同会员允许预约不同排课，即使上课时间重叠。不符合返回对应业务错误并回滚。
5. 保存预约关联 ID、上课时间快照、人数、初始状态已预约和预约时间；条件增加 booked_persons。次数卡按人数扣次并写入原始扣次及余额流水，年卡不扣次。
6. 任一预约、名额、余额或流水写入失败均整体回滚；成功提交后返回 AjaxResult<Void>（code = 200，msg = “预约成功”），不包含 data。相同 requestId 且参数一致的并发重试也返回相同成功响应，不重复创建预约、占位或扣次；参数不同返回 409。
7. 前端收到成功后刷新排课详情、会员卡余额与我的预约列表；响应丢失时使用原 requestId 重试。事务和锁规则见[预约管理详细设计](预约管理详细设计.md)。

## 4.11 取消预约

`PUT /api/reservations/{reservationId}/cancel`

1. 按公共会员鉴权取得 memberId，Controller 校验 reservationId；Service 按预约 ID + 本人会员 ID 定位，不存在或越权统一返回 404。
2. 开启事务，按排课、预约、会员卡顺序加锁并重新检查所有权；已取消时直接返回相同成功响应，不重复释放名额或返次。
3. 取得最新时间，校验预约为已预约、排课已上架且 now <= startTime - 2 小时；已签到或超过截止时间返回 409。
4. 条件更新预约为已取消，写 cancelTime 与会员主动取消原因；按原 persons 减少排课 booked_persons。
5. 次数卡按原扣次流水记录的次数返还原卡并追加返次流水，停卡或过期不阻止返次；年卡不产生次数流水。任一步失败整体回滚。
6. 提交后返回 AjaxResult<Void>（code = 200，msg = “取消预约成功”），不包含 data；前端刷新预约、名额与余额。已取消记录的重复请求返回相同成功响应。

## 4.12 预约签到

`PUT /api/reservations/{reservationId}/check-in`

1. 按公共会员鉴权取得 memberId，校验 reservationId，按预约 ID + 本人会员 ID 定位；不存在或越权统一返回 404。
2. 开启事务，按排课、预约顺序加锁并重新检查所有权；未取消且已有签到时间的记录直接返回相同成功响应。
3. 取最新时间，校验预约为已预约、排课已上架，且 startTime - 30 分钟 <= now < endTime；不满足返回 409。
4. 按 status = 1 条件更新为已签到并写 checkInTime，不修改余额、流水或排课人数；失败回滚。
5. 提交后返回 AjaxResult<Void>（code = 200，msg = “签到成功”），不包含 data；前端刷新预约状态。排课结束不改变预约状态，已有签到记录的重试返回相同成功响应。

## 4.13 查询我的预约

`GET /api/reservations`

1. 按公共会员鉴权取得 memberId，Controller 校验状态、卡类型与分页参数。
2. DAO 固定 member_id = 当前会员，不按首页门店过滤；按接口约定关联排课、会员卡进行筛选，直接按预约存储 status 筛选和统计总数。
3. 按 reservation_time DESC、id DESC 分页；无记录或页码超界时返回空 rows，total 保持筛选结果总数。
4. 按本页排课 ID 批量读取课程、课种、教练和门店地址，仅装配列表模型需要的关联资料；会员卡关联用于卡类型筛选，不额外返回卡片字段。基础展示资料缺失时对应字段返回 null。
5. 起止时间使用预约快照，由 startTime 生成 scheduleDate；预约状态直接读取 status，课程结束不改变预约状态。
6. 转换为精简的 ReservationPublicItemVO 后，将分页总数与 VO 列表包装为 TableDataInfo；只返回模型中列出的字段，不返回排课状态、按钮标识或管理端字段。取消与签到的资格由各自操作接口再次校验，查询不写业务数据。

## 1.3 数据库物理模型

### 1.3.1 建表语句

```sql
CREATE TABLE `t_store` (
  `id`             bigint unsigned NOT NULL COMMENT '门店ID',
  `store_no`       varchar(3)   NOT NULL COMMENT '门店编号',
  `name`           varchar(64)  NOT NULL COMMENT '门店名称',
  `store_type`     tinyint      NOT NULL COMMENT '门店类型：1主力店 2精品店',
  `region_code`    varchar(6)   NOT NULL COMMENT '所在区域',
  `phone`          varchar(32)  NOT NULL COMMENT '联系电话',
  `business_hours` varchar(64)  NOT NULL COMMENT '营业时间展示文本',
  `address`        varchar(255) NOT NULL COMMENT '地址',
  `image_url`      varchar(255) DEFAULT NULL COMMENT '门店图片URL',
  `create_by`      bigint unsigned DEFAULT NULL COMMENT '创建人ID',
  `create_time`    datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by`      bigint unsigned DEFAULT NULL COMMENT '更新人ID',
  `update_time`    datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_store_name` (`name`),
  UNIQUE KEY `uk_store_no` (`store_no`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='门店基础信息表';
```

# 4、运行流程

## 4.1 查询列表

1. Controller 接收并校验 `StoreQuery`（`pageSize` 上限 100）。
2. Service 调 DAO；DAO 选择字段、追加筛选条件与稳定排序。
3. Service 将 DO 转为 `StoreListItemVO`，Controller 装配 `TableDataInfo`。

## 4.2 查询详情

1. Service 按 ID 查询；不存在 → `404`。
2. 转 `StoreDetailVO` 返回。

## 4.3 新增门店

1. Controller 校验必填、长度与枚举（`storeType` ∈ {1,2}；`regionCode` ∈ 字典 `store_region`）。
2. Service 按 `name` 查重；重复 → `409`。
3. Service **生成门店编号**：取当前 `store_no` 最大值 ＋1、零填充 3 位（`BR-门店-011`）；上限 999，超出999报错
4. 转 DO 插入；主键由雪花 ID 生成，审计字段由公共处理器填充。
5. 只返回统一成功响应，不返回新 ID。

## 4.4 修改门店

1. Service 按 ID 查询；不存在 → `404`。
2. 按 `name` 查重（**排除自身**）；重复 → `409`。
3. 全量覆盖业务字段并更新；返回最新详情。
4. **不做引用检查**——已被排课引用时仍允许修改。

## 4.5 删除门店

1. Service 开启数据库事务，按主键 `SELECT ... FOR UPDATE` 锁定本门店行并当前读；不存在返回 `404`。这与排课写入时调用 `StoreService.lockByIdsForUpdate` 获取的是同一行锁，不先做无锁引用检查。
2. 锁内调用 `ClassroomService` 对现存教室做当前读统计；大于 0 返回 `409`，提示教室数量。教室新增也必须先取得同一门店行锁，不能在引用检查后绕过锁创建教室。
3. 锁内调用 `ScheduleService.countActiveByStoreId`，以当前读取得 `end_time > 当前时间 AND status IN (1,2)` 的引用记录并统计；大于 0 返回 `409`，提示“该门店仍有 N 节未结束的排课，无法删除”。已取消或已结束的历史排课不阻塞，历史关联信息按用户端约定空值兜底。
4. 引用统计失败直接终止并回滚，不降级放行。统计与删除必须处于同一数据库事务，同一行锁一直保持到提交／回滚。
5. 无阻塞引用才物理删除并提交。并发排课写请求随后取得门店锁时应发现对象不存在，返回 `404`；已持锁的排课请求若先提交，删除请求取得锁后会看到新引用并被拒绝。死锁或锁等待失败先回滚，再有限重试完整事务，不重试业务门禁失败。

## 4.6 对外加锁契约

`StoreService.lockByIdsForUpdate(ids)` 在调用方已开启的数据库事务内参与执行（不得使用 `REQUIRES_NEW`）。对 ID 去重、升序后逐行按主键 `SELECT id ... FOR UPDATE`，对象缺失抛 `404`；不返回持久化实体，不在方法返回时提前释放锁。排课写入、门店删除锁同一实际数据行；公共顺序为“门店 → 教练 → 课程 → 教室 → 排课”，各类内部按 ID 升序。历史结束任务允许跳过已删除主数据，使用单独的“仅锁现存行”入口，不改变新增／修改排课的存在性要求。

## 1.3 数据库物理模型

### 1.3.1 建表语句

```sql
CREATE TABLE `t_store` (
  `id`             bigint unsigned NOT NULL COMMENT '门店ID',
  `store_no`       char(4) NOT NULL COMMENT '门店编号',
  `name`           varchar(64)  NOT NULL COMMENT '门店名称',
  `store_type`     tinyint      NOT NULL COMMENT '门店类型：1主力店 2精品店',
  `region_code`    varchar(6)   NOT NULL COMMENT '所在区域',
  `phone`          varchar(32)  NOT NULL COMMENT '联系电话',
  `business_hours` varchar(64)  NOT NULL COMMENT '营业时间展示文本',
  `address`        varchar(255) NOT NULL COMMENT '地址',
  `image_url`      varchar(255) NOT NULL DEFAULT 'https://loremflickr.com/cache/resized/4322_35262033823_278218688c_n_320_240_nofilter.jpg' COMMENT '门店图片URL',
  `create_by`      bigint unsigned DEFAULT NULL COMMENT '创建人ID',
  `create_time`    datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by`      bigint unsigned DEFAULT NULL COMMENT '更新人ID',
  `update_time`    datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_store_name` (`name`),
  UNIQUE KEY `uk_store_no` (`store_no`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='门店基础信息表';
```

### 1.3.2 门店编号计数器

```sql
CREATE TABLE `t_store_no_counter` (
  `id`      tinyint unsigned NOT NULL COMMENT '固定为1',
  `last_no` int unsigned NOT NULL COMMENT '已分配的最大门店编号',
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='门店编号计数器';

INSERT INTO `t_store_no_counter` (`id`, `last_no`) VALUES (1, 0);
```

初始化语句仅适用于全新数据库；已有数据按 §4.3.1 初始化，不得重置正在使用的计数器。计数器记录须在开放新增门店前存在，由门店模块在数据库事务中读取并更新。

# 4、运行流程

## 4.1 查询列表

1. Controller 接收并校验 `StoreQuery`（`pageSize` 上限 100）。
2. Service 调 DAO；DAO 选择字段、追加筛选条件与稳定排序。
3. Service 将 DO 转为 `StoreListItemVO`，Controller 装配 `TableDataInfo`。

## 4.2 查询详情

1. Service 按 ID 查询；不存在 → `404`。
2. 转 `StoreDetailVO` 返回。

## 4.3 新增门店

1. Controller 校验必填、长度与枚举（`storeType` ∈ {1,2}；`regionCode` ∈ 字典 `store_region`）；Service 将省略或为空的 `imageUrl` 替换为默认图片后入库。
2. Service 按 `name` 查重；重复 → `409`。
3. 开启数据库事务，锁定 `t_store_no_counter` 中 `id = 1` 的记录；`last_no` 已为 `9999` 时返回 `409`：“门店编号已用尽”。否则递增计数器，将新值补零为四位并写入 DO 的 `store_no`。
4. 在同一事务内插入 DO；主键由雪花 ID 生成，审计字段由公共处理器填充，计数器与门店记录一起提交或回滚。数据库 `uk_store_no` 兜底；编号唯一键冲突回滚并返回 `409`：“门店编号生成冲突，请稍后重试”，不自动重试。`uk_store_name` 冲突仍返回名称重复，其他数据库异常不得归为编号冲突。
5. 只返回统一成功响应，不返回新 ID。

### 4.3.1 门店编号分配规则

1. 门店编号按创建顺序递增，固定为四位数字，从 `0001` 开始，最大为 `9999`；`0000` 不使用。门店 ID 继续使用雪花 ID，业务关联使用 ID，编号用于展示和生成会员卡卡号。
2. 编号由服务端分配，不接受客户端指定或修改。门店改名、搬迁、变更店型时编号保持不变；删除门店后不回收编号，允许跳号。
3. 使用独立的数据库计数器记录已分配的最大编号，不使用门店表的 `MAX(store_no) + 1`。新增门店的事务中，通过 `SELECT ... FOR UPDATE` 锁定计数器，检查上限后递增，将数值补零为四位并写入门店；计数器更新与门店插入一起提交或回滚。
4. 全新数据库将计数器初始化为 `0`。已有数据接入时，先为缺少编号的门店分配唯一编号，将已有编号统一补零为四位，再初始化计数器；初值不得低于任何历史已分配编号。既有会员卡卡号保持不变。
5. 达到 `9999` 后拒绝新增门店并返回 `409`：“门店编号已用尽”。计数器不随门店删除而降低。

## 4.4 修改门店

1. Service 按 ID 查询；不存在 → `404`。
2. 按 `name` 查重（**排除自身**）；重复 → `409`。
3. 将省略或为空的 `imageUrl` 替换为默认图片，覆盖请求中的业务字段并更新；`store_no` 保持不变，返回最新详情。
4. **不做引用检查**——已被排课引用时仍允许修改。

## 4.5 删除门店

1. Service 按 ID 查询门店；不存在返回 `404`。
2. 按 ID 删除门店记录，不回收门店编号、不降低编号计数器，返回统一成功响应。

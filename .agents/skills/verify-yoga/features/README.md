# 瑜伽预约系统验收地图

驱动用户端 H5 前先读本页，再按对应功能文件操作。环境启动、Doctor 和定位规则见 [../SKILL.md](../SKILL.md)。

## 基线前提

- 三个服务已启动，Doctor 全部通过，后端 jar 晚于最后一次后端提交。
- 浏览器会话 `yoga-verify`，视口 390×844。
- 功能脚本已执行 `setup`；种子会员 `13800138000`／`yoga1234` 不用于验收，避免污染用户数据。

## 操作约定

- 每个功能从它自己的 `setup` 开始，不依赖上一个功能留下的状态。
- 页面操作用 `agent-browser --session yoga-verify`；“其他会员”的动作用功能脚本命令扮演。
- 改变数据的步骤之后，用功能脚本 `status` 读一次库核对。

## 证据与跳过

- 截图放 `.verify/<功能>/`（已 gitignore，不提交），每张截图配一条文字输出（`get text`／`get url`／`status`）。
- 某个入口走不通时，记录尝试的命令和缺少的前提，不要用另一个入口代替报告通过。

## 功能

- [会员登录](./login.md)：手机号密码登录，所有会员页面的前置。
- [预约课程](./booking.md)：有空位时直接预约、取消预约。
- [课程排队](./queue.md)：满员排队、排队名次、排队上限与停止排队时间、取消预约后按顺序补位。

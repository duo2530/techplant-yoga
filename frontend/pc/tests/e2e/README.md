# 管理端端到端测试（Playwright）

覆盖 `frontend/pc` 教练管理页的金牌设置流程。正常流程**直连隔离的真实后端**：登录、教练资料修改、
等级读写都走真实接口与数据库；只有「保存失败不提示成功」用响应拦截构造失败分支。

独立目录与独立依赖：这里的 `playwright-core` 不进管理端应用依赖，用系统已安装的 Edge / Chrome
运行，不额外下载 Playwright 自带浏览器。测试跑的是 `npm run build:prod` 的产物，由套件自带的
静态服务托管，并把浏览器发出的 `/prod-api/**` 代理到后端（生产构建的接口前缀是 Nginx 反代用的
`/prod-api`，测试时由该服务代替 Nginx）。依赖目录保留 `package-lock.json`，可用 `npm ci` 复现。

## 隔离保护（必须先读）

本套件会**创建并删除**教练、系统用户（`sys_user`）和角色（`sys_role`），属于破坏性测试。因此
套件**不会使用默认地址静默执行**，必须同时满足：

1. 显式设置 `E2E_API_URL` 指向一次性隔离的 e2e 后端（不依赖 `localhost:8080` 默认值）；
2. 显式设置 `E2E_ALLOW_DESTRUCTIVE=1` 确认允许测试数据变更。

任一缺失时脚本打印风险说明并以**退出码 3** 结束，不会连接后端。**禁止**指向开发库、共享库或
生产环境。用例失败时也会尽力清理已创建的测试数据；清理失败会打印需人工处理的标识。

## 前置条件

| 项 | 要求 |
|---|---|
| Node.js | ≥ 20.19 |
| 管理端产物 | `frontend/pc/dist`（先执行 `npm run build:prod`，或用 `npm run test:build`） |
| 后端 | **一次性隔离的 e2e 环境**已启动，MySQL / Redis 可用；地址通过 `E2E_API_URL` 显式给出 |
| 管理员账号 | `admin` / `admin123`（可用环境变量覆盖），角色具备 `yoga:coach:level` 权限 |
| 菜单 | 教练管理菜单已配置（`yoga.sql` 的 2003 / component `coach/index`），按钮权限 `yoga:coach:level` 已授权 |
| 验证码 | 隔离库 `sys_config` 的 `sys.account.captchaEnabled` 为 `false`，否则登录无法自动化 |
| 浏览器 | 本机已安装 Edge 或 Chrome（找不到时用 `E2E_BROWSER_PATH` 指定） |

关闭验证码（在隔离 e2e 库执行，修改后需刷新后端配置缓存）：

```sql
UPDATE sys_config SET config_value = 'false' WHERE config_key = 'sys.account.captchaEnabled';
```

确认方式：`GET /captchaImage` 返回 `captchaEnabled=false`。若仍为 `true`，脚本会打印上述说明并以
退出码 2 结束，**不会**在验证码开启时假装跑通用例。

## 运行

```powershell
# 1) 先构建管理端产物（在 frontend/pc）
cd frontend/pc
npm run build:prod

# 2) 安装测试依赖（在本目录，lockfile 已入库，用 npm ci 复现）
cd tests/e2e
npm ci

# 3) 显式声明隔离后端与破坏性测试开关后运行
$env:E2E_API_URL = 'http://localhost:8080'
$env:E2E_ALLOW_DESTRUCTIVE = '1'
npm test

# 一步到位：先构建再跑（同样需要上面两个环境变量）
npm run test:build

# 只跑指定 spec（按文件名/稳定英文标识过滤，不用中文用例名）
node run.js --only=coach-level
```

退出码：全部通过为 0，有失败为 1，后端验证码未关闭为 2，缺少隔离开关为 3。

## 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `E2E_API_URL` | 无默认（**必须显式设置**） | 隔离后端地址，静态服务的 `/prod-api` 代理目标 |
| `E2E_ALLOW_DESTRUCTIVE` | 未设置 | **必须为 `1`** 才执行；确认允许创建/删除教练、系统用户与角色 |
| `E2E_PC_DIST` | `frontend/pc/dist` | 管理端构建产物目录 |
| `E2E_ADMIN_USERNAME` | `admin` | 管理员账号 |
| `E2E_ADMIN_PASSWORD` | `admin123` | 管理员密码 |
| `E2E_BROWSER_PATH` | 自动探测 Edge / Chrome | 浏览器可执行文件路径 |
| `E2E_PORT` | `0`（随机端口） | 静态服务端口 |
| `E2E_HEADFUL` | 未设置（无头） | 设为 `1` 时显示浏览器窗口，便于排查 |

## 测试数据

套件用管理员接口自建一个名称唯一的教练（`E2E金牌测试<6 位时间戳>`），用例通过真实等级接口把它的
等级置为前置状态；全部用例结束后通过接口删除该教练，不依赖种子教练数据。教练创建后若取不到 ID，
会按唯一名兜底查询并删除；清理失败时打印需人工处理的姓名与 ID，并以退出码 1 结束。

「无金牌权限账号」用例还会通过 `/system/role`、`/system/user` 新建一个仅含教练菜单（2000、2003）、
不含 `yoga:coach:level` 的角色与账号（`e2e<6 位时间戳>`）。用例结束（含中途失败）时在 `finally`
中按 ID 或唯一标识兜底查询后删除账号与角色。这些接口都要求管理员具备 `system:role:*` /
`system:user:*` 权限，`admin` 超管满足。

## 失败产物

失败时在该目录的 `artifacts/<时间戳>/` 下按用例名留三份材料（已 gitignore）：

- `<用例名>.png`：整页截图
- `<用例名>.trace.zip`：Playwright trace（`npx playwright show-trace <文件>` 打开）
- `<用例名>.log.txt`：断言错误、页面地址、等级接口与资料修改请求、控制台错误与失败请求

## 用例

| 用例 | 覆盖点 |
|---|---|
| 管理员登录并进入教练管理 | 登录页真实登录、`Admin-Token` 写入、「经营基础 → 教练管理」菜单进入列表 |
| 设为金牌后列表与接口一致 | 二次确认、成功提示、列表等级标签、`PUT /admin/coaches/{id}/level?level=2` 契约、刷新后等级仍为金牌 |
| 修改资料保持金牌等级 | 编辑资料成功、资料请求体不含 `level`、后端等级保持 2、简介按提交内容更新 |
| 取消金牌后恢复普通 | `level=1` 调用、成功提示、列表恢复普通、后端等级为 1 |
| 等级保存失败不提示成功 | 真实后端非法等级返回业务码 400 且等级不变；拦截同一业务错误时出现错误提示、无成功提示、等级不变 |
| 无金牌权限账号不显示等级操作 | 用管理端接口创建「有教练菜单、无 `yoga:coach:level`」的角色与账号：页面可进入、等级列正常，但行内不渲染「设为金牌／取消金牌」；该账号直接调用等级接口返回 403 且等级不变（用例结束删除账号与角色） |

## 管理端操作说明（供文档同步）

- 操作路径：登录管理端 → 左侧「经营基础」→「教练管理」→ 列表「等级」列查看普通／金牌 →
  行内「设为金牌」／「取消金牌」按钮 → 二次确认 → 成功提示并刷新列表。
- 权限串：`yoga:coach:level`，与后端 `@PreAuthorize` 严格一致；按钮通过 `v-hasPermi` 控制显示。
  在「系统管理 → 角色管理」为角色勾选「教练管理」下的「教练金牌设置」按钮权限即可授权；管理员
  角色持有 `*:*:*` 时始终可见。菜单与按钮权限由 `backend/sql/yoga.sql` 的 `sys_menu` 种子维护。
- 等级与资料分离：金牌／普通只由独立等级接口维护；新增与修改资料表单不提交 `level`，后端资料
  更新也不接管该字段，因此编辑资料不会改变等级。

## 不覆盖范围

- 教练新增／删除的完整 CRUD、其他管理端页面：本次只补金牌标记相关的管理端最小入口。
- 等级接口的完整错误矩阵（非法教练 404、重复设置幂等、审计字段落库）由后端集成测试覆盖；
  本套件只验证页面链路、非法等级 400 与无权限 403 两个失败分支。
- 微信开发者工具、真机与小程序能力；管理端为桌面 Web，不涉及移动视口验收。
- 登录验证码开启时的自动化登录：图形验证码无法由脚本识别，需在隔离库关闭验证码。

测试策略、运行方式与验证要求的统一口径见 [AI Agent测试手册](../../../../docs/系统测试/AI%20Agent测试手册.md)。
